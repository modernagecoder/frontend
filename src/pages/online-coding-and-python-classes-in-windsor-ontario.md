## A Windsor student's program crashes. Here is what the teacher does

This is a reconstruction, written by us, of a moment that happens in some form in most of our Python classes. The code and the error are real: we ran them on the City of Windsor playground file on 22 October 2026.

**One debugging moment in a live online class, in order (our reconstruction; the error text is Python's own)**

| Moment | On the shared screen | What the teacher says or does |
|---|---|---|
| 1. The crash | The student's parse() function stops with ValueError: not enough values to unpack (expected 2, got 1) | Nothing yet. The teacher waits for the student to read the message aloud |
| 2. Reading it | The student reads the last line, then the line number it points to | &ldquo;Expected 2, got 1. Two of what?&rdquo; |
| 3. A guess | The student says key, value = part.split("=") wanted two pieces but got one | &ldquo;Good. Which row gave it one piece? How could you find out?&rdquo; |
| 4. Looking | The student prints each description before parsing it and sees a blank one on line 3 of the file | &ldquo;What does split give you for an empty string?&rdquo; |
| 5. The fix | The student adds if "=" in part: and runs the program again over all 131 rows | Asks how many rows had nothing to parse. The answer is 14 |
| 6. The habit | The student writes one comment explaining the guard | &ldquo;Next time a file crashes your program, what will you do first?&rdquo; |

Six short steps, and the teacher never typed. That is the difference between a live class and a recorded one: the recording would have shown a tidy program that never crashed, and the student would have copied it. In our classes the error is the lesson, and the student leaves knowing how to read the next one without help.

### In a group class

With fifteen to twenty students at one stage, the teacher puts one student's crash on the shared screen and the whole group reasons through it. Often several of them have the same bug.

### In a one to one class

The same six steps, at the student's own pace. One to one suits students working on an ICS4U project or preparing for the CCC.

### The setup

A laptop or desktop, a microphone and Python installed with the teacher in the first lesson. The student shares their editor; the teacher never takes the keyboard.

**Our Python stages by the errors a student learns to handle, with related Ontario wording (ministry text in quotation marks; stages ours)**

| Stage (ours) | Errors the student can fix alone | Ontario link |
|---|---|---|
| 1. First programs | SyntaxError: a missing bracket, quote or colon | Grades 11 and 12 courses open with the strand &ldquo;Programming Concepts and Skills&rdquo; (2008 document) |
| 2. Variables and types | NameError and TypeError: a misspelled name, text added to a number | MTH1W C2: &ldquo;apply coding skills to represent mathematical concepts and relationships dynamically&rdquo; |

Stage 3 is the turning point. Up to stage 2, Python tells the student something is wrong. From stage 3 on, the program runs and the answer is simply incorrect, and only a student who predicted the answer first will notice. That is why every class asks for a prediction before the run, from a child's first loop to a teen's data project.

## How many Windsor playgrounds does the city file mark as accessible, ward by ward?

The City of Windsor publishes a playground layer as open data, 131 rows on our download of 22 October 2026. Size and accessibility are not separate columns; they are packed into one text field such as SIZE=MEDIUM, ACCESSIBLE=YES, so a program has to parse them. All figures below are our own output.

**Our count from the City of Windsor playground file (131 rows, downloaded 22 October 2026): rows per political_ward and rows whose description contains ACCESSIBLE=YES**

| Ward | Playground rows | Marked ACCESSIBLE=YES |
|---|---|---|
| Ward 1 | 16 | 8 |
| Ward 2 | 15 | 6 |
| Ward 3 | 9 | 6 |
| Ward 4 | 12 | 4 |
| Ward 5 | 14 | 4 |
| Ward 6 | 11 | 7 |
| Ward 7 | 19 | 3 |
| Ward 8 | 9 | 3 |
| Ward 9 | 12 | 6 |
| Ward 10 | 14 | 5 |

This is the corrected program from the debugging moment above, with the guard in place. It reads the CSV with the standard csv module, turns each description into a small dictionary, and counts with Counter:

```
import csv
from collections import Counter

def parse(description):
    info = {}
    for part in description.split(","):
        if "=" in part:
            key, value = part.split("=")
            info[key.strip()] = value.strip()
    return info

sizes = Counter()
accessible_by_ward = Counter()
with open("playground.csv", encoding="utf-8-sig", newline="") as f:
    for row in csv.DictReader(f):
        info = parse(row["asset_description"])
        sizes[(info.get("SIZE", "not given"), info.get("ACCESSIBLE", "not given"))] += 1
        if info.get("ACCESSIBLE") == "YES":
            accessible_by_ward[row["political_ward"]] += 1

for (size, access), n in sorted(sizes.items()):
    print(size, access, n)
print(accessible_by_ward.most_common())
```

### Size against access

Parsed, the descriptions give LARGE with ACCESSIBLE=YES on 28 rows and LARGE with NO on 9; MEDIUM YES 13, MEDIUM NO 33; SMALL YES 10, SMALL NO 23. One row gives accessibility without a size, and 14 give neither.

### Themes

Twenty-seven rows also carry a THEME, with 24 different values: Forest appears three times and Pirate Ship twice, and single rows include Automotive, Aviation, Dinosaur and Space Ship.

### Ward 7

Ward 7 has the most playground rows, 19, and only 3 of them are marked ACCESSIBLE=YES. Ward 3 has 9 rows and 6 marked YES. The next question is why, and the file alone cannot answer it.

### What ACCESSIBLE=YES does and does not tell you

It records a label in the City's asset description, not an inspection a student has made, and 14 rows have no description at all, so a missing YES is not a NO. Seven park_id values also end in a stray space, which would split one park into two if a student grouped by park. Reporting the counts with those caveats is the finished project.

## Can a Windsor student let AI fix the bugs instead?

It can fix this bug. It cannot teach the student to find the next one.

Paste the ValueError into an AI assistant and it will suggest the same guard our student wrote. What it will not do is make the student look at line 3 of the file, count the 14 blank descriptions, or notice the stray spaces in park_id. The fix arrives; the understanding does not.

We teach the reasoning first: read the error, form a guess, test it, then fix. Older students use AI tools later within the age rules we follow, as a second opinion to check, never as the place answers come from.

A Windsor student who can explain why a missing ACCESSIBLE=YES is not the same as a NO has learned the part of coding that stays human. The longer argument is in [what students still need to learn about code](/blog/is-coding-worth-learning-2026).
