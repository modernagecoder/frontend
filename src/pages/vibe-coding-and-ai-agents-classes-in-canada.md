## Vibe coding, agents and MCP, defined by their sources

These terms are used loosely in advertising. Here they are as the dictionary, the agent builders and the protocol's own site define them, read on 22 October 2026.

**Definitions from primary sources (read 22 October 2026)**

| Term | Source | What the source says |
|---|---|---|
| Vibe coding | Collins Dictionary, Word of the Year 2025 (November 6, 2025) | "Coined by AI pioneer Andrej Karpathy, vibe coding refers to the use of artificial intelligence prompted by natural language to write computer code." |
| Workflow | Anthropic, Building effective agents (Dec 19, 2024) | "Workflows are systems where LLMs and tools are orchestrated through predefined code paths." |
| Agent | The same article | Agents "are systems where LLMs dynamically direct their own processes and tool usage". |
| Agentic coding tool | Claude Code documentation | "Claude Code is an agentic coding tool that reads your codebase, edits files, runs commands, and integrates with your development tools." |
| MCP | modelcontextprotocol.io | "MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems." |

### The difference that matters in practice

In a workflow, a programmer decides the steps and the model fills in parts of them. In an agent, the model decides the steps. That one change explains most of what goes right and wrong: an agent can solve a problem nobody scripted, and it can also wander, repeat itself, or act on a mistaken guess.

Vibe coding sits at the human end of the same scale. A person describes the result, the AI writes code, and the person decides whether to keep it. The skill that separates a good vibe coder from a bad one is reading what came back.

### What we teach first

Before any agent, learners write the tools themselves: small functions with clear inputs, outputs and failure messages. An agent is only as reliable as the tools it calls and the checks wrapped around its answer.

Anthropic's own advice points the same way: "we recommend finding the simplest solution possible, and only increasing complexity when needed." Many problems never need an agent at all.

## What AI agents can do, and what they cannot

Agents are sold as autonomous workers. The people who build them are more careful. This table combines Anthropic's published guidance with what our own small agent below showed.

**Agents: strengths and limits (Anthropic's guidance, quoted; our test results, labelled)**

| Question | What the evidence says |
|---|---|
| Can an agent handle a task nobody scripted? | Yes. Anthropic: agents suit cases where "flexibility and model-driven decision-making are needed at scale". |
| Is an agent always the right choice? | No. Anthropic recommends "finding the simplest solution possible, and only increasing complexity when needed." |
| What does autonomy cost? | Anthropic: "higher costs, and the potential for compounding errors." |
| How should agents be tested? | Anthropic: "We recommend extensive testing in sandboxed environments, along with the appropriate guardrails." |
| Can an agent state something its tools never returned? | Yes. Our stand-in plan below names a park, "Maple Leaf Dog Run", that is not in the city's file. Only the check catches it. |
| Does an agent understand data it was not told about? | No. The Ottawa file codes dog rules as 0 to 4. Nothing in a code says that 0 means off leash and 4 means not designated; the agent knows only what its tool description says. |

### Good at

Repetitive changes across many files, first drafts of tests, exploring an unfamiliar codebase, and joining tools a person has already made reliable.

### Weak at

Knowing when it is wrong, respecting a rule nobody wrote down, and stopping when the task is unclear. It will often produce a confident answer instead.

### Needs from you

Clear tools, a test you can run, version control to undo its changes, and a check that compares its answer with what its tools actually returned.

## An Ottawa parks agent whose answers are checked

The City of Ottawa publishes its parks and greenspace under a licence that allows commercial reuse, including a coded rule for dogs in each park. We built a small agent loop around it to show every part an agent needs: tools, a loop that runs them, and a check on the final answer. The code and every number are ours, run on the city's file downloaded on 22 October 2026.

The question an agent is asked: "Which parks in Kanata North let my dog off leash?" The file has 1,378 rows across 24 wards, with columns including NAME, WARD_NAME, DOG_DESIGNATION and DOG_DESIGNATION_DETAILS, the city's own wording for each park's rule.

**What the DOG_DESIGNATION codes mean, read from the city's own detail text (our tally of the file)**

| Code | The city's wording, most common form | Parks |
|---|---|---|
| 0 | "Dogs may be off leash." (with a line about the handler's control) | 175 |
| 1 | "Dogs are allowed but must be on leash at all times." | 356 |
| 2 | Area-specific, for example off leash in a fenced area and on leash elsewhere | 69 |
| 3 | "Dogs are not allowed in the park." | 119 |
| 4 | "The park has not been designated." (then on-leash wording) | 631 |
| Blank | No code given | 28 |

**Our agent loop · park_agent.py** (python)
```python
# Our park agent: a tool loop with a checked answer (Modern Age Coders, written for this page)
import csv

PARKS = list(csv.DictReader(open("ottawa-parks.csv", encoding="utf-8-sig")))
DOG_CODES = {"off_leash": "0", "on_leash": "1", "mixed": "2", "no_dogs": "3", "not_designated": "4"}

def find_parks(ward, dog_rule):
    """Tool 1: park names in a ward with a given dog rule."""
    code = DOG_CODES[dog_rule]
    return [p["NAME"] for p in PARKS if p["WARD_NAME"] == ward and p["DOG_DESIGNATION"] == code]

def park_details(name):
    """Tool 2: address and the city's own dog wording for one park."""
    for p in PARKS:
        if p["NAME"] == name:
            return {"address": p["ADDRESS"], "dogs": p["DOG_DESIGNATION_DETAILS"]}
    return {"error": "no park called " + name}

TOOLS = {"find_parks": find_parks, "park_details": park_details}

def run(model_steps):
    """The loop: run each tool call the model asks for, keep every result, check the final answer."""
    seen = set()
    for step in model_steps:
        if step["type"] == "tool":
            result = TOOLS[step["name"]](**step["args"])
            names = result if isinstance(result, list) else [step["args"].get("name", "")]
            seen.update(names)
            print("tool", step["name"], "->", len(names) if isinstance(result, list) else result.get("address", result))
        else:
            unsupported = [n for n in step["parks"] if n not in seen]
            print("answer:", step["parks"][:3], "..." if len(step["parks"]) > 3 else "")
            print("check:", "OK" if not unsupported else "REJECTED, no tool result for " + ", ".join(unsupported))

# Stand-in for a model: a fixed plan, so the loop can be tested without any AI service.
found = find_parks("Kanata North", "off_leash")
honest = [{"type": "tool", "name": "find_parks", "args": {"ward": "Kanata North", "dog_rule": "off_leash"}},
          {"type": "tool", "name": "park_details", "args": {"name": found[0]}},
          {"type": "answer", "parks": found}]
invented = honest[:1] + [{"type": "answer", "parks": found[:2] + ["Maple Leaf Dog Run"]}]

run(honest)
run(invented)
```

**Output on the city's file** (text)
```text
tool find_parks -> 11
tool park_details -> 5599 Campeau Drive, Kanata
answer: ['Kanata Town Centre Stormwater Pond', 'Judy Laughton Park', 'Village Green Stormwater Facility'] ...
check: OK
tool find_parks -> 11
answer: ['Kanata Town Centre Stormwater Pond', 'Judy Laughton Park', 'Maple Leaf Dog Run']
check: REJECTED, no tool result for Maple Leaf Dog Run
```
Kanata North has 95 parks; 11 carry code 0. The honest plan passes the check. The plan that adds a park its tools never returned is rejected.

### Why the stand-in, and what replaces it

The model is replaced here by a fixed plan, clearly marked, so the loop and its check can be run and tested on any laptop without an AI service. That is how we test agent code in class: the plan that a model would produce is written out by hand first, including a bad one.

In the adult course the fixed plan is swapped for calls to a model through its API, and nothing else changes: the same tools, the same loop, the same check. For teens, the same exercise is done with tools their age allows.

### Three weaknesses we leave in on purpose

park_details returns the first park with a matching name, but 16 names appear more than once in the file. A better tool takes the PARK_ID instead. Learners find this themselves by asking for a name that repeats.

The check only proves each named park came from a tool; it cannot prove the agent asked the right question. And the meaning of codes 0 to 4 lives in our DOG_CODES table, which we wrote by reading the city's text. If the city changed its codes, the agent would be confidently wrong. Each of these is a class discussion.

## Why we teach vibe coding as a reading skill

Our promise is the same in every country: learners are taught to think a problem through and solve it, not to copy an answer or an AI's output. With vibe coding that promise is tested hardest, so we make it concrete.

### Predict before accepting

Before running AI-written code, the learner says what it should do and where it might fail. Accepting code you could not predict is how bugs reach users.

### Explain every line

Anything a learner submits, they can explain line by line. A line they cannot explain is rewritten by them, by hand.

### Write the check first

For agents, the test or the answer check is written before the agent runs, exactly as in the Ottawa example.

The Collins definition describes vibe coding as "telling a machine what you want rather than painstakingly coding it yourself". Collins adds: "It's programming by vibes, not variables." That is a fair description of the first step. Our classes are about every step after it, where the variables come back.

## Vibe coding and AI agents in Canada: common questions

### What is vibe coding?

Collins Dictionary, which made it its Word of the Year 2025, says vibe coding refers to the use of artificial intelligence prompted by natural language to write computer code. In our classes it is the first step; reading and testing what the AI wrote is the rest.

### What is the difference between an AI agent and a workflow?

In Anthropic's definitions, a workflow runs models and tools through predefined code paths, while an agent lets the model direct its own process and tool use. Agents are more flexible and also more prone to compounding errors.

### Can teenagers take vibe coding classes?

Yes. Our Vibe Coding for Teens course is for ages 13 to 17 and uses only tools whose terms allow the student's age, such as GitHub Copilot for verified students and, with a parent's permission, OpenAI's tools.

### Can a teen use Claude or Claude Code?

No. Anthropic's terms say users must be at least 18 years old. We never recommend Claude or Claude Code to anyone under 18; they appear only in our adult courses.

### Is there an AI agents course for adults in Canada?

Yes. Our Codex and Claude Code course for professionals runs 24 live classes over 12 weeks, from agent foundations to securing and shipping. Vibe Coding for College covers building full stack projects with AI assistance for ages 18 and up.

### Do I need to know how to code first?

It helps but is not required. Every course starts by teaching learners to read code, because judging AI-written code is the core skill. Adults new to programming often take a Python course alongside.

### Can AI agents replace programmers?

We make no such claim. Anthropic's own guidance warns of higher costs and compounding errors and recommends testing agents in sandboxed environments. Our own small agent shows an answer naming a park its tools never returned; only a check caught it.

### Can students use AI tools in the Canadian Computing Competition?

No. The CCC rules forbid generative AI and AI-based tools inside an editor during the contest, so contest practice happens without assistants.

### What times are classes in Canada?

Weekdays or weekends, flexible: choose your batch, or for a very personalised plan choose 1-on-1 at your convenience, weekend mornings or weekdays. Every time is set in your own province's zone.

### What will I build?
