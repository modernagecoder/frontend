# Coding for international school students in Berlin

A computer science pupil in Berlin can be heading for four very different exams: Cambridge IGCSE, the IB Diploma, an American AP exam, or the Berlin Abitur. They test the same ideas, yet one is on paper in pseudocode, one is on a screen in Java, and one lets you use a computer for every task. ## How do IGCSE, IB, AP and the Berlin Abitur test programming?

The ideas overlap almost completely: variables, loops, arrays, searching, sorting, classes, data. What differs is the medium, the language and how much the computer is allowed to help.

### Paper versus screen

Cambridge asks for algorithms written by hand, in pseudocode or a real language, and its syllabus says the last question of Paper 2 is a 15-mark unseen scenario. A pupil who has only ever typed code into an editor that catches errors finds this hard: there is no red underline on paper.

The College Board does the opposite for AP Computer Science A: the exam is fully digital, taken in the Bluebook app, and the Java Quick Reference is built in. The four free-response questions are fixed in type: methods and control structures, class design, data analysis with an ArrayList, and a 2D array.

### The Berlin Abitur

The Informatik-Monitor says Berlin's written Abitur tasks in Informatik are developed decentrally: the teacher submits two proposals for a course and one is chosen. Working on a computer is allowed in every task, limited to the parts where it is needed for the subject.

Before the Oberstufe, pupils at Berlin's German schools meet computing in the ITG, the Informationstechnischer Grundkurs of one weekly hour, placed in grade 7 or grade 8; after that Informatik is normally an elective of two hours a week across grades 9 and 10. An international school pupil who moves into a Berlin Oberstufe may therefore meet classmates with two years of school Informatik behind them, or none.

Dates matter too. The College Board lists AP Computer Science A on Wednesday 12 May 2027 in Session 2, and its start-time table gives 1:00 p.m. local time for Session 2 at UTC+2, which is Berlin's offset in May. Check your own school's time with the College Board lookup. Cambridge and the IB publish their own timetables, and your school's exams officer has the final version.

## What does Berlin's Christmas market data teach about validating input?

Every computing syllabus asks pupils to validate data. Real data makes the point far better than a textbook, and the Senate's list of Christmas markets is real, messy and open.

### The data

The Senate department for economics publishes Berliner und Brandenburger Weihnachtsmärkte as open data under CC BY. We downloaded the JSON version on 3 November 2026: 48 markets for the 2025/26 season, each with a district, a start date (von), an end date (bis) and free-text opening hours.

The dates are written the German way, day.month.year, as text. A program has to turn that text into a date before it can compare or subtract anything, and that is where the trouble starts.

### The question

How long does a typical market run? It sounds like one subtraction per market. Try it on all 48 and the program crashes, because some cells hold no date, some hold several dates on separate lines, and one says a market ends in 2012.

So Version 1 does what an examiner wants to see: before computing anything, it sorts every record into a named case. Only the clean cases go forward.

**Version 1: classify every record first** (Python)
```python
import json
from datetime import datetime

def parse(text):
    return datetime.strptime(text.strip(), "%d.%m.%Y").date()

markets = json.load(open("weihnachtsmaerkte.json", encoding="utf-8"))["index"]
kinds = {}
for m in markets:
    start, end = m["von"], m["bis"]
    if start == "":
        kind = "no start date"
    elif "\n" in start:
        kind = "several dates in one cell"
    elif end == "":
        kind = "one day only"
    elif parse(end) < parse(start):
        kind = "ends before it starts"
    else:
        kind = "clean range"
    kinds[kind] = kinds.get(kind, 0) + 1

for kind, n in sorted(kinds.items(), key=lambda kv: -kv[1]):
    print(kind, n)
```
It prints clean range 26, one day only 17, several dates in one cell 3, no start date 1 and ends before it starts 1.

Only 26 of 48 records are clean ranges. Seventeen are single-day markets with no end date at all, which is not an error but a different kind of record. Three put several weekend dates into one cell, separated by line breaks. One has no start date in its own field; its dates are hidden in the opening-hours text. And one ends before it starts.

**Version 2: reject what cannot be true, then measure** (Python)
```python
import json
import statistics
from datetime import datetime

def parse(text):
    return datetime.strptime(text.strip(), "%d.%m.%Y").date()

markets = json.load(open("weihnachtsmaerkte.json", encoding="utf-8"))["index"]
spans = []
for m in markets:
    start, end = m["von"], m["bis"]
    if start == "" or "\n" in start or end == "":
        continue
    days = (parse(end) - parse(start)).days + 1
    if days < 1:
        print("Rejected:", m["name"], start, end)
        continue
    spans.append(days)

spans.sort()
print("Clean ranges:", len(spans))
print("Shortest:", spans[0], "Longest:", spans[-1], "Median:", statistics.median(spans))
```
It prints Rejected: Weihnachtsmarkt Königs Wusterhausen 12.12.2025 14.12.2012, Clean ranges: 26 and Shortest: 1 Longest: 124 Median: 35.0.

The rejected record starts on 12 December 2025 and ends on 14 December 2012, which looks like a typing slip, but a program should not guess. It reports the record and leaves it out. The longest clean range is 124 days, a winter market in Mitte from 28 November 2025 to 31 March 2026, which is why we report the median, 35 days, rather than the mean: one long run would pull an average up.

**The 48 records of the 2025/26 season by validation case (our calculation)**

| Case | Records | What a careful program does |
|---|---|---|
| Clean range | 26 | Parse both dates and measure |
| One day only | 17 | Treat as a one-day range, or count separately |
| Several dates in one cell | 3 | Split on line breaks, then pair the dates |
| No start date | 1 | Flag for a human; do not read free text blindly |
| Ends before it starts | 1 | Reject and report |

Data: Senatsverwaltung für Wirtschaft, Energie und Betriebe, Berliner und Brandenburger Weihnachtsmärkte, via Berlin Open Data and GovData, licence CC BY; downloaded 3 November 2026. The list includes five markets in Brandenburg. Every count and duration is our own.

1. **IGCSE.** Write the classification of Version 1 as pseudocode in the Cambridge style, with a CASE statement, then trace it by hand for three records.
2. **AP Computer Science A.** Write a Java class Market with a constructor and a method durationDays() that throws an exception when the end is before the start. Test it with the 2012 record.
3. **IB.** Extend Version 2 so that the three multi-date cells are split and paired, and say how many single weekends that adds.
4. **Abitur.** Draw a state diagram for a date parser that reads characters one by one and accepts only dd.mm.yyyy.
