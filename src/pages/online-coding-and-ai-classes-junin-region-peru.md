## When are the sunniest three hours of the day at Huayao?

The Instituto Geofísico del Perú measures sunlight every hour at its Huancayo observatory at Huayao and publishes the readings as open data. Our older students use them to learn the sliding window, one of the most useful patterns in programming, and what to do when a day has holes in it.

### The dataset

The IGP's atmospheric physics and radiation laboratory, LAMAR, publishes "Estación BSRN para el Balance Energético Solar Tierra-Atmósfera de LAMAR - Junín, Perú" on datosabiertos.gob.pe, with an Open Data Commons Attribution licence (ODC-By). It was last updated on 29 May 2026. The station is at the Huancayo-Huayao observatory, at latitude -12.0424 and longitude -75.3189; its location code, 120904, is the district of Huáchac in Chupaca province.

Our copy of the 2025 file, saved as bsrn-2025.csv, has one row for every hour of 2025, 8,760 in all. We use the column global_SW_rad, the global shortwave irradiance in watts per square metre: in plain words, how strongly the sun is shining on a flat surface.

### The holes

The column is blank in 1,684 of those hours. The IGP explains part of it: the station was moved to a six-metre tower, and because of trouble with its solar tracker, "No se cuenta con datos durante todo el mes de marzo del 2025." March is entirely empty, and other months have scattered gaps.

So the question, which three hours in a row get the most sun on a typical day, has to be answered with data that is missing in places. That is the realistic version of almost every data problem.

**Version 1: brute force, complete days only** (Python)
```python
import csv

days = {}
with open("bsrn-2025.csv", newline="", encoding="utf-8") as station:
    for row in csv.DictReader(station):
        key = (int(row["month"]), int(row["day"]))
        days.setdefault(key, [None] * 24)
        if row["global_SW_rad"] != "":
            days[key][int(row["hour"])] = float(row["global_SW_rad"])

starts = {}
complete = 0
for hours in days.values():
    if None in hours:
        continue
    complete += 1
    peak = max(range(22), key=lambda s: sum(hours[s:s + 3]))
    starts[peak] = starts.get(peak, 0) + 1

print("Days in the file:", len(days))
print("Days with no gap:", complete)
print("Peak three hours start at:", max(starts, key=starts.get))
```
It prints: Days in the file: 365, Days with no gap: 92 and Peak three hours start at: 11.

Version 1 works, but look at what it threw away. It only uses days with no gap at all, and because a single blank hour, even at night, ruins a day, only 92 of 365 days survive. It also adds up every three-hour slice from scratch, which is fine here and wasteful on longer data. The answer, a window starting with the reading labelled 11, is reasonable, but it rests on a quarter of the year.

Version 2 slides a three-hour window along each day. It keeps a running total and a count of gaps: when an hour enters the window, it is added (or the gap count goes up); when an hour leaves, it is taken away (or the gap count goes down). A window is only considered when its gap count is zero, so a blank hour at midnight no longer spoils the afternoon. It also flags any day whose peak window starts before six in the morning, because that cannot be right for sunlight.

**Version 2: a sliding window that skips gaps, not days** (Python)
```python
import csv

days = {}
with open("bsrn-2025.csv", newline="", encoding="utf-8") as station:
    for row in csv.DictReader(station):
        key = (int(row["month"]), int(row["day"]))
        days.setdefault(key, [None] * 24)
        if row["global_SW_rad"] != "":
            days[key][int(row["hour"])] = float(row["global_SW_rad"])

def best_window(hours, width=3):
    total, gaps, peak = 0.0, 0, None
    for h in range(24):
        if hours[h] is None:
            gaps += 1
        else:
            total += hours[h]
        if h >= width:
            leaving = hours[h - width]
            if leaving is None:
                gaps -= 1
            else:
                total -= leaving
        if h >= width - 1 and gaps == 0:
            if peak is None or total > peak[0]:
                peak = (total, h - width + 1)
    return peak

starts = {}
odd = []
for key, hours in days.items():
    found = best_window(hours)
    if found is None or found[0] < 1:   # night, or no daylight in any gap-free window
        continue
    starts[found[1]] = starts.get(found[1], 0) + 1
    if found[1] < 6:
        odd.append(key)

print("Days we can use:", sum(starts.values()))
print("Most common starts:", sorted(starts.items(), key=lambda p: -p[1])[:3])
print("Check by hand (month, day):", odd)
```
It prints: Days we can use: 317, Most common starts: [(11, 139), (10, 70), (9, 39)] and Check by hand (month, day): [(10, 21)].

Now 317 days count instead of 92, and the answer holds: on 139 of them the sunniest three hours begin with the reading labelled 11, and on most of the rest they begin at 10 or 9. The check catches one day, 21 October 2025. Opening it shows why: that day has daylight readings only at 6, 12, 13, 15 and 16, so every window covering the middle of the day contains a gap, and the "peak" complete window is in the early morning. The program did exactly what it was told; the flag makes sure a person looks before anyone trusts that day. One more detail for the curious: running totals of decimals can leave a tiny leftover such as 0.00000000000003 instead of zero, which is why Version 2 ignores totals under 1.
