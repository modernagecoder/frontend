### Computational thinking, defined

The page defines computational thinking as &ldquo;formulating problems and their solutions so they are represented in a form that can be solved through an algorithmic process.&rdquo; That is a useful sentence for a student to keep. It says the hard part happens before the code: turning a messy situation into something precise enough for a machine.

Its big ideas say the design cycle &ldquo;is an ongoing reflective process&rdquo; and that &ldquo;Tools and technologies can be adapted for specific purposes.&rdquo; In practice, a CP 11 student is marked on how they plan, test and improve a program, not only on whether the final version runs.

### Pair programming is assessed work, not a shortcut

Parents sometimes worry when they hear that their teen codes with a partner. The curriculum names pair programming as content, with clear roles: the driver types, the navigator reviews each line as it appears, and they swap often. Done well, it catches mistakes early and makes both students explain their thinking aloud.

We practise it on screen. The student drives while the teacher navigates, then they swap, so the student learns to review code as carefully as they write it. That second skill is the one most teenagers have never been asked to use.

### The jump students feel

Grade 11 programs usually fit in one file and one sitting. Grade 12 projects do not. Once a program spreads across several files, a student needs a way to find which file holds the fault, and the curriculum&rsquo;s answer is a real debugger: step through, watch the variables, find the line where reality parts from the plan.

### Error handling, the CP 12 way

The curriculum breaks error handling into anticipation, detection and resolution. Anticipation means asking what a user could type that would break the program. Detection means the program notices. Resolution means it recovers with a clear message instead of a crash.

## Estimating a probability by simulation, then checking it exactly

Computer Science 11 lists &ldquo;estimate theoretical probability through simulation&rdquo; as content. This problem is ours. It does the simulation and then does something students often skip: it works out the exact answer by counting, so the simulation can be judged against the truth.

The problem. Roll two fair six-sided dice. What is the probability that the sum is at least 10? Estimate it by simulating 100, 1,000, 10,000 and 100,000 rolls, then compute the exact value and compare.

1. Count before you code. Two dice give 6 &times; 6 = 36 equally likely ordered pairs. Sums of 10, 11 and 12 come from (4, 6), (5, 5), (6, 4), (5, 6), (6, 5) and (6, 6): six pairs. So the exact probability is 6 out of 36, one sixth, about 0.1667. The program checks this count with a nested loop instead of trusting our list.
2. Separate the jobs. One function counts exactly; another simulates. Each can be tested alone, the decomposition the curriculum describes.
3. Fix the seed. A random number generator started with the same seed gives the same sequence, so a teacher, a partner and the student all see identical output. Without it, nobody can check anybody else&rsquo;s run.
4. Measure the error, not just the estimate. Print how far each estimate is from the exact answer. The interesting result is in that column.

**Python · dice simulation (ours)** (python)
```python
# Two dice, sum of at least 10: simulation against the exact answer (ours)
import random

def exact_chance(target):
    """Count the 36 equally likely (die1, die2) pairs whose sum is at least target."""
    hits = 0
    for a in range(1, 7):
        for b in range(1, 7):
            if a + b >= target:
                hits += 1
    return hits, 36

def simulate(trials, target, seed):
    rng = random.Random(seed)      # a fixed seed makes the run repeatable
    hits = 0
    for _ in range(trials):
        if rng.randint(1, 6) + rng.randint(1, 6) >= target:
            hits += 1
    return hits / trials

hits, outcomes = exact_chance(10)
print("Exact:", hits, "of", outcomes, "=", round(hits / outcomes, 4))
for n in [100, 1000, 10000, 100000]:
    est = simulate(n, 10, seed=11)
    print(f"{n:>6} trials: {est:.4f}  (off by {abs(est - hits / outcomes):.4f})")
```

**Output, Python 3.13** (text)
```text
Exact: 6 of 36 = 0.1667
   100 trials: 0.1200  (off by 0.0467)
  1000 trials: 0.1610  (off by 0.0057)
 10000 trials: 0.1663  (off by 0.0004)
100000 trials: 0.1681  (off by 0.0015)
```
Same seed, same output on any machine running Python 3. Change the seed and the estimates change; the exact line never does.

### What the output teaches

One hundred rolls gave 0.12, a long way from 0.1667. A student who stopped there would believe the chance is about one in eight. A thousand rolls came within 0.006, and ten thousand within 0.0004.

Then the surprise: 100,000 rolls landed 0.0015 away, further than 10,000 did. That is not a bug. A simulation&rsquo;s error tends to shrink as trials grow, but any single run can wobble. This is the &ldquo;connection between theoretical and experimental probability&rdquo; the curriculum&rsquo;s competencies mention, seen in four lines of output.

### Where students go wrong

The common mistake is random.randint(2, 12) for the sum of two dice. It picks each sum from 2 to 12 equally, which is wrong: a 7 can happen six ways and a 12 only one. The simulation then reports about 3 in 11, roughly 0.27, and a student without the exact count never notices.

The second mistake is counting only six of the 36 outcomes by hand and forgetting that (4, 6) and (6, 4) are different rolls. The nested loop removes that risk, which is why it is worth writing even when the answer seems obvious.

## A Pacific-to-India clock converter that refuses bad input

This one is in the Computer Programming spirit: a small tool for a real user, with requirements, error handling and a test table. It is ours, and it solves a question BC families ask us: if a class is at 4:30 in the afternoon in Vancouver, what time is it for the teacher?

1. Write the requirements first. Input: a 24-hour time as HH:MM in BC. Output: the time in India and whether it is the same day or the next. BC has been on UTC-7 all year since March 2026 and India is on UTC+5:30, so the gap is 12 hours 30 minutes, always.
2. Anticipate. List what a user could type wrongly: a missing colon, single-digit minutes, letters, an hour of 24, minutes of 60.
3. Detect. Check the shape of the input, then the ranges. Let Python&rsquo;s own int() detect letters, because it already raises an error for them.
4. Resolve. Catch each error where the program is used and print a message that tells the user how to fix it, instead of a traceback.
5. Fill in the expected column before running. Then run every case and compare.

**Python · clock converter (ours)** (python)
```python
# Pacific time to India time, with error handling (ours)
# BC is UTC-7 all year from 8 March 2026; India is UTC+5:30, so India is 12 h 30 min ahead.
GAP_MINUTES = 12 * 60 + 30

def parse_clock(text):
    """Turn 'HH:MM' (24-hour) into minutes after midnight, or raise ValueError."""
    parts = text.strip().split(":")
    if len(parts) != 2 or len(parts[1]) != 2:
        raise ValueError("use the form HH:MM, for example 16:30")
    hours, minutes = int(parts[0]), int(parts[1])   # int() raises ValueError on letters
    if not (0 <= hours <= 23 and 0 <= minutes <= 59):
        raise ValueError("hours run 0 to 23 and minutes 0 to 59")
    return hours * 60 + minutes

def to_india(text):
    total = parse_clock(text) + GAP_MINUTES
    day = "next day" if total >= 24 * 60 else "same day"
    total %= 24 * 60
    return f"{total // 60:02d}:{total % 60:02d} ({day})"

for entry in ["16:30", "09:00", "11:29", "11:30", "23:59", "24:00", "7:5", "ab:30", "four"]:
    try:
        print(entry, "->", to_india(entry))
    except ValueError as err:
        print(entry, "-> rejected:", err)
```

**Test plan for the converter: expected written first, actual from the run (ours; all nine rows match)**

| Input | Expected and actual output | What the case tests |
|---|---|---|
| 16:30 | 05:00 (next day) | A typical after-school time crosses midnight in India |
| 09:00 | 21:30 (same day) | A weekend morning in BC is the evening in India |
| 11:29 | 23:59 (same day) | The last minute before the day changes |
| 11:30 | 00:00 (next day) | Exactly midnight counts as the next day |
| 23:59 | 12:29 (next day) | The largest valid input |
| 24:00 | rejected: hours run 0 to 23 and minutes 0 to 59 | An hour that does not exist |
| 7:5 | rejected: use the form HH:MM, for example 16:30 | Single-digit minutes are ambiguous |
| ab:30 | rejected: invalid literal for int() with base 10: 'ab' | Letters, caught by int() itself |
| four | rejected: use the form HH:MM, for example 16:30 | No colon at all |

### Why the boundaries matter

Rows three and four differ by one minute and give different days. A converter written with > instead of >= in the next-day check passes almost every test and fails at 11:30. Boundary cases exist to catch exactly that, and the curriculum&rsquo;s test-case content asks students to compare expected with actual output for this reason.

The ab:30 row shows a judgement call. Python&rsquo;s message is accurate but unfriendly. A CP 12 student might wrap it in a clearer sentence; a CS 11 student might leave it, since the program still refuses the input. Both choices can be defended, and defending the choice is part of the work.

### One fixed gap, one exception

The program can use a single fixed gap because BC no longer changes its clocks. Before 2026 the same code would have needed two gaps, one for summer and one for winter. That is a nice discussion question in itself: what assumption is built into a constant, and what would break if it changed?

The fixed gap is also not true everywhere in BC. East Kootenay and Golden keep UTC-6 all year, one hour ahead of Vancouver, so a family there needs a gap of 11 hours 30 minutes. A good requirements list would say which region the tool is for.

## Answers, with the reasoning

Each program here was run in Python 3.13 to confirm the output. The reasoning is the part to learn; the number at the start is only the check.

1. 0b1101 11 0xff. Thirteen is 8 + 4 + 1, so binary 1101, and Python prefixes binary with 0b. The string 1011 read in base 2 is 8 + 2 + 1 = 11. Two hundred fifty-five is 15 &times; 16 + 15, so hexadecimal ff, prefixed 0x.
2. 2 5. The count inside bump is a local variable, created by the assignment on its first line. It starts at 1, becomes 2 and is returned. The global count outside was never touched, so it is still 5: local versus global, exactly as the CS 11 content names it.
3. The two columns are identical: True, True, True, False for the rows FF, FT, TF, TT. That is one of De Morgan&rsquo;s laws: not (a and b) equals (not a) or (not b). The other law gives not (raining or windy) = (not raining) and (not windy).
4. 4. When i is 1, j takes only 0. When i is 2, j takes 0 and 1, adding 1. When i is 3, j takes 0, 1 and 2, adding 3. The total is 0 + 1 + 3 = 4. The inner loop runs i times, because range(i) stops before i.
5. For 31: indexes 3, then 5. The first middle is (0 + 6) // 2 = 3, holding 19, which is too small, so lo becomes 4; the next middle is (4 + 6) // 2 = 5, holding 31. For 10: indexes 3, 1, 2, then lo passes hi and the search reports not found. A linear search checks 3, 8, 12, 19, 25 and 31: six checks to find 31.
6. It prints 18. The line a = b overwrites a before the remainder is taken, so a % b becomes 18 % 18 = 0 and the loop ends at once. Both new values must come from the old pair: a, b = b, a % b. Then 48, 18 becomes 18, 12, then 12, 6, then 6, 0, and the answer is 6. That is Euclid&rsquo;s algorithm.
7. It prints [4, -5, 7]. Removing an item while looping over the same list shifts everything after it one place left, so the loop skips the item that slid into the removed one&rsquo;s place. After -2 is removed, -5 slides into its index and is never examined. Build a new list instead: [t for t in temps if t >= 0].
8. 12 and 42 (see the code below). The least common multiple is a &times; b divided by the greatest common factor. Dividing first keeps the intermediate number small, which matters little in Python but prevents overflow in Java with large ints.
9. See the code below. Our six tests and results: V6B 1A1 True; K1A 0B1 True; v6b 1a1 False (lower case); V6B1A1 False (no space); V6B 1AA False (letter where a digit belongs); the empty string False. The length check comes first so that a short string never reaches the loop.
10. One good set: (1) store member names and meeting dates; (2) for each meeting, record present or absent for every member; (3) a member is reported when they are absent at three meetings in a row, in date order; (4) the report lists each such member once, with the dates missed. For the hour: the driver codes the data entry while the navigator writes the test table for requirement 3, then they swap. Writing requirement 3 precisely (is &ldquo;three in a row&rdquo; three meetings or three weeks?) is the real lesson.

**Answers 6 and 8 · Python** (python)
```python
def gcf(a, b):
    while b != 0:
        a, b = b, a % b      # both new values come from the old pair
    return a

def lcm(a, b):
    return a // gcf(a, b) * b   # divide first so the product stays small

print(gcf(48, 18), lcm(4, 6), lcm(21, 6))   # 6 12 42
```

**Answer 9 · Python** (python)
```python
def is_postal_code(text):
    """True for letter digit letter, space, digit letter digit, e.g. V6B 1A1."""
    if len(text) != 7 or text[3] != " ":
        return False
    pattern = "LDL DLD"
    for ch, kind in zip(text, pattern):
        if kind == "L" and not (ch.isalpha() and ch.isupper()):
            return False
        if kind == "D" and not ch.isdigit():
            return False
    return True
```
Run against the six inputs above, it returns True, True, False, False, False, False in that order. A regular expression can do the same in one line; for a CS 11 test, the loop shows the reasoning a marker wants to see.

## A study plan for tests and project deadlines

BC senior programming courses are assessed in different ways by different teachers: tests, coding tasks done in class, and projects with a written process. This plan is ours. It covers both kinds of assessment; drop the half that your teen&rsquo;s course does not use.

1. Get the assessment list from the teacher. Which pieces are tests, which are in-class coding tasks, which are projects, and what does each project hand in besides code: a plan, a test table, a reflection?
2. Keep a vocabulary page. Variable, constant, scope, parameter, return value, decision structure, nested loop, syntax error, semantic error, run-time error, logic error. One line of definition and two lines of example each.
3. For tests, trace on paper daily. Two short programs a day with a written trace table. Questions 2, 4 and 5 above are the shape to practise.
4. For CS 11, drill the logic and number topics. Convert five numbers between decimal, binary and hexadecimal each week, and prove one logical equivalence with a truth table.
5. Rebuild the standard algorithms from a blank file. Linear search, binary search, greatest common factor, a running total and a count. No notes; then compare with class versions.
6. For projects, write requirements before code. A numbered list, agreed with the teacher if possible. Every later decision gets checked against it.
7. Keep a test table from day one. Expected results written before running, boundary cases included, like the converter table above.
8. Save a working version at every milestone. A project that worked on Tuesday and is broken on Thursday should never be a disaster. Version control is the grown-up answer; a dated copy of the folder is the minimum.
9. Practise with a partner. If the course uses pair programming, rehearse both roles. Navigating well, catching a mistake as it is typed, is a skill that improves only with practice.
10. Finish early, then improve. Stop adding features a week before a deadline. Use that week for testing, documentation and the written reflection.

**A four-week run-up to a unit test or project deadline (ours)**

| Weeks to go | For a test | For a project |
|---|---|---|
| 4 | Vocabulary page complete; topics marked solid or shaky | Requirements written and agreed; plan drawn |
| 3 | Daily tracing; standard algorithms rebuilt | Core features working; test table started |
| 2 | Timed practice on shaky topics | All requirements met in a saved version |
| 1 | One full timed practice and a mistakes log | Testing, documentation and reflection only |

## Computer Programming 11 and 12: common questions

### What is Computer Programming 11 in BC?

Computer Programming 11 is a BC Applied Design, Skills, and Technologies course. Its content includes problem decomposition, pair programming, programming constructs for input and output, logic, decisions and loops, turning requirements into algorithms, pre-built libraries and their documentation, and test cases that compare expected and actual output.

### Is Computer Science 11 the same as Computer Programming 11?

No. Computer Science 11 is a Mathematics course and Computer Programming 11 is an ADST course. Both teach programming, but Computer Science 11 adds logic such as truth tables and De Morgan's laws, number systems, searching algorithms and modelling mathematical problems, while Computer Programming 11 centres on design, pair work and testing.

### Do you grant Computer Programming 11 or 12 credit?

No. We teach alongside the student's school course and we do not grant provincial credits. The credit comes from the school that teaches and assesses the course, such as the student's own school, a district summer school or an online learning school.

### What does Computer Programming 12 add?

Bigger, longer projects. Code gets organized into functions, methods or classes, and the list adds documentation with industry standard tools, self-documenting code, user interface design, error handling, a debugger that steps through code, projects with multiple source files, pre-built data structures, and bug reports and feature requests from users.

### Which language do BC computer courses use?

The curriculum pages we read do not fix a language, so it depends on the teacher; ask which one the class uses. We teach in whichever language that is, most often Python or Java, and the practice set on this page is in Python.

### What is in Computer Science 12?

Computer Science 12 is on the BC Mathematics course list. Its content page did not load when we returned to the curriculum site on 22 October 2026, so we do not describe it here. Bring the teacher's outline to the first class and we plan from that.

### Do I need Computer Programming 12 for computer science at UBC?

Not according to UBC's own list. For BC applicants to Science at UBC Vancouver, the requirements tool we read on 22 October 2026 asked for a Grade 12 English, Pre-Calculus 12, one Grade 12 science, and Chemistry 11 and Physics 11. It named no programming course.

### Is pair programming allowed, or is it cheating?

It is part of the course. Computer Programming 11 names pair programming as content: one student, the driver, types while the other, the navigator, reviews each line, and they switch roles often. Copying another pair's work is a different matter, and teachers treat it as such.

### How should my teen prepare for a Computer Science 11 test?

Keep a vocabulary page, trace two short programs on paper each day, practise binary and hexadecimal conversions and truth tables, and rebuild linear search, binary search and the greatest common factor from a blank file. A timed practice in the last week shows what still needs work.
