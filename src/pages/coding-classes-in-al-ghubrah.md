## The assigned Al Ghubrah project: percent versus percentage points

The dataset is entirely synthetic. Period A has 20 successes among 500 attempts. Period B has 30 successes among 500 attempts. The rates are 4% and 6%.

```python
old_rate = 20 / 500  # 0.04
new_rate = 30 / 500  # 0.06

point_change = (new_rate - old_rate) * 100
relative_change = ((new_rate - old_rate) / old_rate) * 100
```

The output gives a 2-percentage-point increase and a 50% relative increase. Both are correct:

- percentage-point change is `6% - 4% = 2 points`;
- relative percentage change is `(6% - 4%) / 4% = 50%`;
- the absolute count change is `30 - 20 = 10` additional successes.

"Up two percent" is not acceptable because it does not say which calculation was used. "Up fifty percent" needs the original 4% baseline and preferably the counts, because a relative number alone can make a modest absolute change sound dramatic.

A defensible sentence is: "The synthetic success rate rose from 4% (20 of 500) to 6% (30 of 500), an increase of 2 percentage points or 50% relative to the earlier rate."

The learner must preserve the denominators and the time window. If Period B instead contained 30 successes among 1,000 attempts, its rate would be 3%, despite the higher count. If the definition of success changed, direct comparison might be invalid. Correct arithmetic cannot repair incompatible measurements.

An extension writes a formatter that always shows the old rate, new rate, absolute counts, point change and relative change. The code also needs a defined response when the original rate is zero, because relative change then requires division by zero. The program should return an explicit not-defined state rather than infinity or a promotional phrase.

No number in this exercise is an Indian School Al Ghubra examination result, a health rate or a claim about district residents.
