## ¿Cómo busca un programa un nombre en una lista?

Recorriéndola de principio a fin, y esperando hasta el final para decir que no está. Este ejercicio lo escribimos nosotros para chicos de 10 a 12 años: buscar a Rosa en la lista del equipo, primero con un error muy común y luego bien.

**Dos versiones de la misma búsqueda** (Python)
```python
team = ['Ana', 'Luis', 'Rosa', 'Teo']
wanted = 'Rosa'

print('Version 1')
for name in team:
    if name == wanted:
        print('Found', wanted)
    else:
        print('Not found')

print('Version 2')
found = False
for name in team:
    if name == wanted:
        found = True
if found:
    print('Found', wanted)
else:
    print('Not found')
```
La versión 1 decide en cada vuelta del bucle. La versión 2 usa una variable found, que empieza en False y solo cambia si aparece el nombre; la decisión se toma después del bucle.

**Lo que se ve en la pantalla** (Salida)
```salida
Version 1
Not found
Not found
Found Rosa
Not found
Version 2
Found Rosa
```
Salida copiada sin cambios después de ejecutar el archivo con Python 3. La versión 1 dice "Not found" tres veces aunque Rosa sí está en la lista.

1. **Buscar con el dedo.** El mentor muestra la lista y pregunta: "Is Rosa on the team?" Todos dicen que sí. Luego, "How many times should the program answer?" Una sola vez.
2. **Ejecutar la versión 1.** Aparecen cuatro respuestas, tres de ellas falsas. El programa dijo "Not found" ante Ana, ante Luis y ante Teo, porque decidió con cada nombre en lugar de esperar al final.
3. **Encontrar el error.** El problema está en el else dentro del bucle. Comparar con un nombre que no es Rosa no significa que Rosa no esté; solo significa que todavía no apareció.
4. **Arreglarlo con una bandera.** La variable found funciona como una bandera que se levanta al ver a Rosa. Después de revisar toda la lista se mira la bandera y se responde una sola vez.
5. **Probar los casos difíciles.** ¿Qué pasa si se busca a "Pedro", que no está? ¿Y si la lista está vacía? El niño lo prueba y explica en inglés por qué la versión 2 responde bien.

Lo vemos una y otra vez en programas pegados desde la web o producidos por un chatbot: el código contesta algo, y si uno no lo lee con cuidado parece correcto. Enseñamos a desconfiar de la primera respuesta, a probar casos que podrían romper el programa y a explicar por qué funciona. Sobre ese enfoque escribimos en [programar con IA sin copiar](/programar-con-ia-sin-copiar).

Cualquier día y a cualquier hora, con total flexibilidad: elija una clase grupal o, para un plan muy personalizado, clases individuales a la hora que mejor le convenga a su familia.
