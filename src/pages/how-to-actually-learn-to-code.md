# You do not learn by watching. You learn by being stuck and getting out.

> The feeling of understanding and the fact of understanding are different quantities, and most popular learning formats optimise the first. Watching a competent person solve a problem produces genuine comprehension of each step while building almost no ability to produce it, which is why students finish long video courses and still cannot start from an empty file. Skill is built in the moments of being stuck, so Modern Age Coders teaches live in small batches with blank-file starts, build work between sessions and a teacher who declines to rescue a student too early. It is slower and less comfortable in the first month and we say so before anyone enrols. Group teaching is USD 100 a month, private is USD 150, first class free.

## Two quantities that come apart

When you watch somebody competent solve a problem, each step is obvious as it happens and your brain produces a strong, genuine feeling of comprehension. That feeling is a report on how easy the material was to **follow**, which is a different quantity from how well you can **produce** it.

Most courses widen the gap, because a course that feels hard gets worse reviews than one that feels smooth. Hence the familiar figure: forty hours of video, six projects built by following instructions, unable to start from an empty file. Nobody misled them. The work measured the wrong thing.

## Two sessions, the same eight lines

The first took nine minutes and felt excellent: follow along, everything makes sense, it works.

The second took thirty-six and felt like failure. Blank file, wrong, read the error, fix the decorator, works, now the id is a string, find the converter, type it wrong twice, works, missing item returns a server error, learn what abort is for, done, ugly, mine.

Every gap in the second session is a moment of being stuck, and every one of those is where the learning happened. Not when it worked. When the error had to be read with nothing to copy from.

## Six practices

1. **Close the tutorial and rebuild it from nothing**, the next day, with the tab shut.
2. **Get stuck on purpose and stay there twenty minutes.** The effort of not finding the answer is the mechanism.
3. **Build something nobody has a tutorial for.** Also where most self-taught learners quit, which is why a teacher helps.
4. **Finish things, even badly.** The last twenty per cent contains everything nobody demonstrates.
5. **Explain it without notes.** Speaking forces retrieval in a way rereading cannot.
6. **Space it out.** Ninety minutes weekly for a year beats a forty-hour week, and it is not close.

## Signals

| | Feels like learning | Actually is learning |
|---|---|---|
| In the moment | Smooth, makes sense | Slow, mildly frustrating |
| Your role | Following an example | Producing from blank |
| Afterwards | Confident | Unsure, but able to repeat it |
| A week later | Mostly gone | Mostly still there |

## Six traps

Tutorial hopping. Waiting to feel ready to build. Optimising the setup. Choosing a language purely on job listings. Reading about code instead of writing it. And the newest one: **asking an assistant at the first difficulty**, which removes exactly the interval that would have built the skill and hides the loss because working code still appears.

## What this costs you

We are slower to start and less comfortable. A student following a tutorial builds something impressive in week one; a student here builds something ugly in week three and can rebuild it in week four. For families comparing early visible output we lose that comparison, and we would rather explain why than change the method.
