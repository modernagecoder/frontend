## The Barka date-sorting project

The learner builds a small timeline using four real publication labels and their cited sources:

| Display label | ISO date | Event type | Source subject |
|---|---|---|---|
| 3 November 2021 | 2021-11-03 | Operations announcement | Khazaen Dry Port |
| 11 August 2025 | 2025-08-11 | Customs-corridor announcement | Khazaen Dry Port |
| 16 September 2025 | 2025-09-16 | Agreement signature | Barka Fort |
| 18 March 2026 | 2026-03-18 | Inspection publication | Silal |

The first implementation sorts the `display_label` field alphabetically. The order begins with labels starting 11, 16 and 18 and pushes the label starting 3 later. The 2021 event therefore appears below 2025 and 2026 records. Every source row is accurate; the timeline is not.

Text sorting compares characters from left to right. It does not understand that the last four characters represent a year, that August comes before September, or that 3 is an earlier day than 11 within the same month. A human-readable label is not automatically a date value.

The repair parses each label using a declared day-month-year format and English month names. The program stores an ISO date such as `2021-11-03` or a proper database date. It sorts by the parsed field while preserving the original label for display and the URL for provenance.

The event type also remains explicit. Publication, announcement, agreement, inspection, start and planned completion are not interchangeable. Sorting a single date field cannot repair an ambiguous claim.

## A safe date-import pipeline

| Stage | Required rule | Failure prevented | Result |
|---|---|---|---|
| Capture | Keep label, claim and source URL | Lost context | Auditable raw row |
| Parse | Declare format and locale | Day-month ambiguity | Typed date or error |
| Validate | Reject impossible and incomplete values | Silent rollover | Quarantine queue |
| Sort | Use date or timestamp field | Alphabetical timeline | Chronological order |
| Display | Render for the audience | Machine value replacing readable text | Label backed by typed data |

Test cases include leap years, impossible dates, empty strings, duplicate events and timestamps around midnight. An impossible 31 February row can be generated for the test suite, but it is labelled synthetic and never mixed with the four cited Barka records.

Younger learners can order cards with separate year, month and day fields. Learners aged 11 to 13 can compare spreadsheet date cells with text cells. Teenagers can write parsers in Python or JavaScript and test invalid input. Adults can add database date types, timezone rules, import logs and review queues.

The core lesson is broader than formatting: data should be stored in a type that matches the operation. Display labels serve readers; typed dates serve chronology.
