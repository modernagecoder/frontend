# Coding in the Ontario math curriculum, Grades 1 to 8

Since the 2020 math curriculum, every Ontario child from Grade 1 to Grade 8 is expected to write code in math class. The wording changes each year, one or two words at a time, and those words decide what a child should be able to do by June. Below is the expectation for every grade, quoted from the ministry&rsquo;s own curriculum site, then what each step looks like in a real program, written and run by us.

## The C3.1 coding expectation, Grade 1 to Grade 8

In every grade the overall expectation is the same sentence: students will &ldquo;solve problems and create computational representations of mathematical situations using coding concepts and skills&rdquo;. What changes is the specific expectation C3.1, which ends &ldquo;by writing and executing code, including code that involves&rdquo; and then names that year&rsquo;s idea. This table quotes the part that changes.

**C3.1 by grade, quoted from the Ontario elementary mathematics curriculum (2020), read 22 October 2026; the last column is ours**

| Grade | C3.1 asks for code that involves | A line from the curriculum&rsquo;s notes | What it looks like (ours) |
|---|---|---|---|
| 1 | &ldquo;sequential events&rdquo; | &ldquo;In coding, a sequential set of instructions is executed in order.&rdquo; | A route of arrow cards across a floor grid |
| 2 | &ldquo;sequential and concurrent events&rdquo; | &ldquo;Concurrent events are when multiple things are occurring at the same time&rdquo; | Two Scratch sprites moving at once |
| 3 | &ldquo;sequential, concurrent, and repeating events&rdquo; | &ldquo;Loops make code more readable and reduce the number of instructions that need to be written.&rdquo; | A repeat block that walks a rectangle and adds up its sides |
| 4 | &ldquo;sequential, concurrent, repeating, and nested events&rdquo; | &ldquo;Loops can exist within loops, referred to as &lsquo;nested loops&rsquo;.&rdquo; | A loop inside a loop that draws a 3 by 4 array |
| 5 | &ldquo;conditional statements and other control structures&rdquo; | &ldquo;Conditional statements are a representation of binary logic (yes or no, true or false, 1 or 0).&rdquo; | Checking whether 47 belongs to a number pattern |
| 6 | the same as Grade 5, but now &ldquo;efficient code&rdquo; | &ldquo;Using loops whenever possible is one way to make code more efficient.&rdquo; | Adding 1 to 100 two ways and counting the work |
| 7 | &ldquo;events influenced by a defined count and/or subprogram and other control structures&rdquo;, still &ldquo;efficient code&rdquo; | &ldquo;Sub-programs can be reused for multiple programs or can be called upon more than once from one main program.&rdquo; | A function that counts doublings, called three times |
| 8 | &ldquo;the analysis of data in order to inform and communicate decisions&rdquo; | &ldquo;By combining mathematical and coding concepts and skills, students can write programs to draw conclusions from data.&rdquo; | A week of garden rainfall turned into a watering decision |

**C3.2, reading and altering code, by grade (same curriculum, same date)**

| Grades | C3.2 in the curriculum&rsquo;s words |
|---|---|
| 1 to 5 | &ldquo;read and alter existing code&rdquo; that involves that grade&rsquo;s idea, &ldquo;and describe how changes to the code affect the outcomes&rdquo; |
| 6 and 7 | The same, plus how changes affect &ldquo;the outcomes and the efficiency of the code&rdquo; |
| 8 | &ldquo;read and alter existing code involving the analysis of data in order to inform and communicate decisions, and describe how changes to the code affect the outcomes and the efficiency of the code&rdquo; |

### Three things the table shows

First, the ideas pile up rather than replace each other. Grade 4 still lists sequential and concurrent events; it simply adds nesting on top. A Grade 4 child who never got comfortable with plain repetition is being asked to put a loop inside a loop.

Second, the word &ldquo;efficient&rdquo; enters C3.1 in Grade 6 and stays in Grade 7, then drops out of the Grade 8 C3.1 sentence, where data takes centre stage. Efficiency does not vanish in Grade 8: C3.2 still asks how changes affect &ldquo;the efficiency of the code&rdquo;.

### And the third

Every C3.1 is about mathematical situations, not about coding for its own sake. The Grade 3 list of possible situations includes &ldquo;determining perimeter&rdquo;; the Grade 1 list starts with &ldquo;moving from one location to another&rdquo;. The code is a way of doing math out loud, where the computer checks the thinking.

That is why our examples below are all math problems first. A child who can explain why the program prints what it prints has met the expectation, whatever tool they used.

## What the coding expectations mean, in plain language

The curriculum&rsquo;s notes are short and precise. Five of them settle most of the questions parents ask us, starting with which program a child should use.

### No tool is prescribed

The notes for Grades 1 to 4 say: &ldquo;Coding can include a combination of pseudocode, block-based coding programs, and text-based coding programs.&rdquo; Neither Scratch nor Python is named in any of the eight grade documents we read.

### Code can run on a person

Children can program &ldquo;a pixelated image on a screen, a classmate acting out the code when appropriate, or a physical device (e.g., robot, microcontroller)&rdquo;. A Grade 1 lesson with no computer at all can meet C3.1.

### Order sometimes matters

A Grade 3 note on C3.2 says: &ldquo;It is important for students to understand when order matters.&rdquo; Adding steps in any order gets the same total; turning then moving is not the same as moving then turning.

### One equal sign or two

From Grade 5, the notes draw a line that trips up many beginners: &ldquo;Assignment statements assign a value to a variable and usually use a single equal sign (=), while comparison statements are used to compare two values and usually use a double equal sign (==)&rdquo;.

In math class, the equal sign says two sides are the same. In most code, a single equal sign means &ldquo;put this value in this box&rdquo;. A child who writes total = total + 4 is not writing a false equation; they are updating a running total. We spend a whole lesson on that one difference.

### What &ldquo;efficient&rdquo; means here

The Grade 6 notes define it: &ldquo;Efficient code may involve using the instructions to solve a problem, using the smallest amount of space to store program data, and/or executing as fast as possible.&rdquo; At this age that mostly means fewer instructions doing the same job, often by using a loop instead of copying a line ten times.

Grade 7 adds the defined count: &ldquo;A defined count is used to repeat an instruction either for a predefined number of times (e.g., 10 repeats) or until a condition has been met (e.g., Number <= 100).&rdquo; The doubling example further down is exactly that second kind of loop.

Coding also turns up outside math. The 2022 Science and Technology curriculum asks Grade 6 students to &ldquo;use coding in investigations and to model concepts, and assess the impact of coding and of emerging technologies on everyday life&rdquo;, and its A2.1 adds &ldquo;with a focus on obtaining input in different ways&rdquo;. So a Grade 6 child may meet coding twice a week in two subjects, with two teachers using two different tools.

## What each band of the coding curriculum looks like in practice

These are our own examples, written for this page. The early ones are described as Scratch blocks or classroom activities; from Grade 4 on they are Python programs that we ran, with the output printed under each. None is taken from the curriculum&rsquo;s own sample tasks.

### Grades 1 and 2: a route, then two things at once

Grade 1, unplugged. Tape a 5 by 5 grid on the floor and put a toy at one corner. The child lays arrow cards in a row (forward, forward, turn right, forward) and a parent walks the route exactly as written. If the parent ends up in the wrong square, the child finds the card that is wrong. That is writing, executing, reading and altering a sequential program.

Grade 2, in Scratch. Two sprites, a cat and a bus, each get their own script that starts with the green flag. The bus glides across the road while the cat counts to ten. The concurrent part is that both scripts run at the same moment; the math is in how many steps each glide takes and which one arrives first.

### Grade 3: one loop does the walking

A sprite walks around a rectangle that is 60 steps long and 40 steps wide. Written out in full, that is eight blocks: move, turn, move, turn, and so on. With a repeat block set to 2 around &ldquo;move 60, turn 90, move 40, turn 90&rdquo;, it is one loop with four blocks inside.

Then the math: add a variable called perimeter, and inside the loop add 60 and 40 to it. The sprite finishes at 200. Ask the child to change the repeat to 3 and predict the new perimeter before pressing the flag. The answer, 300, is wrong for a rectangle, and the child has to say why.

**Grade 4 · nested loop · Python (ours)** (python)
```python
# Grade 4 band: a nested loop draws an array (ours)
rows = 3
columns = 4
dots = 0
for r in range(rows):
    line = ""
    for c in range(columns):
        line = line + "o "
        dots = dots + 1
    print(line)
print(rows, "rows of", columns, "is", dots, "dots")
```
Output: three rows of o o o o, then 3 rows of 4 is 12 dots. The inner loop runs four times for every one turn of the outer loop, which is multiplication made visible: change rows to 5 and the program prints 20 dots.

**Grade 5 · a conditional inside a loop · Python (ours)** (python)
```python
# Grade 5 band: is a number in the pattern 5, 9, 13, ...? (ours)
target = 47
term = 5
found = False
while term <= target:
    if term == target:
        found = True
    term = term + 4
if found:
    print(target, "is in the pattern")
else:
    print(target, "is not in the pattern")
```
Output: 47 is not in the pattern. The terms go 5, 9, 13 and on to 45, then 49, which jumps past 47. The if asks a yes-or-no question on every term, which is the binary logic the Grade 5 notes describe.

**Grade 6 · efficiency · Python (ours)** (python)
```python
# Grade 6 band: two ways to add 1 + 2 + ... + 100 (ours)
steps = 0
total = 0
for n in range(1, 101):
    total = total + n
    steps = steps + 1
print("Loop:", total, "after", steps, "additions")

last = 100
quick = last * (last + 1) // 2
print("Pairing rule:", quick, "after 1 calculation")
```
Output: Loop: 5050 after 100 additions, then Pairing rule: 5050 after 1 calculation. Pair 1 with 100, 2 with 99, and so on: 50 pairs of 101. Same answer, one calculation instead of a hundred, which is what C3.2 means by the efficiency of the code.

**Grade 7 · a subprogram with a defined count · Python (ours)** (python)
```python
# Grade 7 band: a subprogram with a defined count (ours)
def doublings_past(start, limit):
    """How many times must start double before it is more than limit?"""
    count = 0
    value = start
    while value <= limit:
        value = value * 2
        count = count + 1
    return count

print(doublings_past(3, 100))
print(doublings_past(5, 1000))
print(doublings_past(1, 1))
```
Output: 6, 8 and 1. Starting from 3, five doublings reach 96 and the sixth jumps to 192, past 100; 5 needs eight to pass 1000; 1 needs one. The loop runs until a condition is met, not a fixed number of times, and the function is written once and called three times.

**Grade 8 · data to a decision · Python (ours)** (python)
```python
# Grade 8 band: use data to make a decision (ours)
rain_mm = [12, 0, 4, 0, 0, 7, 0]   # one week of rain in the school garden

def mean(values):
    return sum(values) / len(values)

week_mean = mean(rain_mm)
spread = max(rain_mm) - min(rain_mm)
dry_days = 0
for r in rain_mm:
    if r == 0:
        dry_days = dry_days + 1

print("Mean:", round(week_mean, 1), "mm a day")
print("Range:", spread, "mm")
print("Dry days:", dry_days)
if dry_days >= 4:
    print("Decision: water the garden on dry days")
else:
    print("Decision: no extra watering")
```
Output: Mean: 3.3 mm a day, Range: 12 mm, Dry days: 4, then Decision: water the garden on dry days. The mean alone would hide the dry spell; the count of dry days is what drives the decision. Asking which measure to trust is the Grade 8 skill.

## Reading and altering code: our predict, change, predict routine

Every grade&rsquo;s C3.2 asks children to read code someone else wrote, change it, and explain what the change did. We teach that as a routine with six steps, using the Grade 5 pattern program above. It works the same way on a Scratch script in Grade 2.

1. Read it aloud, line by line. &ldquo;The target is 47. The first term is 5. While the term is not past the target, check it, then add 4.&rdquo; If a line cannot be said in words, that line is the first thing to teach.
2. Predict before running. Write the prediction down: in or not in? A child who guesses &ldquo;in&rdquo; because 47 is odd has found a real misconception to work on.
3. Run it and compare. The program prints that 47 is not in the pattern. The gap between the prediction and the output is where the lesson is.
4. Change exactly one thing. Set target = 45. Predict again, then run: 45 is in the pattern. One change at a time is the only way to know which change did what.
5. Change the rule, not the number. Set the step from 4 to 3 and the first term to 2, so the pattern is 2, 5, 8 and so on. Is 47 in it now? (Yes: 2 plus 15 threes is 47.)
6. Explain the effect in a sentence. &ldquo;When I changed the step, the program checked a different pattern, so the answer changed.&rdquo; That sentence is the &ldquo;describe how changes to the code affect the outcomes&rdquo; half of C3.2, and it is the half children most often skip.

### Adding efficiency in Grades 6 and 7

From Grade 6, C3.2 adds a second question after every change: did the code get more or less efficient? In the pattern program, there is a faster test. Subtract the first term, 47 minus 5 is 42, and check whether 42 divides evenly by 4. It does not, so 47 is out, with no loop at all.

We ask students to write both versions and count how many times the loop body runs for a target of 4,001. The loop version checks 1,000 terms before reaching it; the remainder test does one division. Children remember the idea far better once they have counted the cost themselves.

### Mistakes worth making on purpose

Change term <= target to term < target and test with 45. The loop now stops one term too early, after checking 41, so the program says 45 is not in the pattern. Off-by-one errors like this follow students all the way to high school computer science, so we plant them early.

Change the starting value of found to True and every number is suddenly in every pattern. A child who can explain why has understood that a variable remembers whatever it was last told.

## Unplugged, Scratch or Python: which tool fits which grade

Because the curriculum leaves the tool open, schools and boards differ. This is how we match tools to the grades, based on teaching young children online since 2020. It is our approach, not a ministry rule.

**Our tool plan for the Ontario coding expectations (ours)**

| Grades | Main tool | Why at this age | Ready to move on when |
|---|---|---|---|
| 1 and 2 | Unplugged cards, then ScratchJr or Scratch | Reading is still developing; arrows and blocks carry the logic without typing | The child can fix a wrong route without being told which card is wrong |
| 3 and 4 | Scratch | Repeat blocks and loops inside loops are visible as shapes inside shapes | They choose a loop without prompting when a step repeats |
| 5 and 6 | Scratch, then first Python | Conditionals and variables read naturally as words; typing speed is usually enough | They can predict a short program&rsquo;s output on paper |
| 7 and 8 | Python | Functions, lists and data need a text language to stay readable | They write a function, call it twice and test an edge case |

### When the school tool is different

Some Ontario classrooms use a block editor, a robot or a microcontroller kit instead of Scratch. The ideas carry over: a loop is a loop. In our first class we ask which tool the class uses and show the child how today&rsquo;s idea looks in both.

For families comparing the two big options, our article on [Scratch vs Python for young learners](/blog/scratch-vs-python-which-better-young-learners) sets out the trade-offs, and [Scratch not working](/scratch-not-working-help) covers the common home-computer problems.

### Screens and safety for young coders

For Grades 1 and 2 we keep sessions short and mix in unplugged tasks, so a lesson is not forty minutes of staring at a screen. Scratch accounts for children can be set up by a parent, and we never ask a child to create an account on their own.

We do not use chatbots or AI code generators with elementary students. The point of C3.1 is that the child writes and executes the code; a program the child did not write teaches them nothing about sequence, loops or conditions.

## How to support the coding expectations at home

Most parents did not learn to code in elementary school, and none of this needs a parent who can. Here is the plan we give families, in the order we suggest it.

1. Find out the tool. Ask the teacher which program or device the class codes with this term, and whether code appears on report-card comments under math.
2. Find the grade&rsquo;s key word in the table above. Sequential, concurrent, repeating, nested, conditional, efficient, defined count, data. That one word is what this year is about.
3. Play it unplugged first. Give spoken instructions to make a sandwich or walk to the door, and let the child debug yours. Sequence and order make sense in the body before they make sense on a screen.
4. Ask for a prediction every time. &ldquo;What will happen when you press the flag?&rdquo; is the single most useful question a parent can ask, and it needs no coding knowledge.
5. Change one thing together. Pick one number in your child&rsquo;s project and change it. Ask what changed on screen and why.
6. Keep the math in sight. Ask what the code is calculating: steps, a total, a pattern rule. If nobody can say, the project is a cartoon rather than math.
7. Save the projects. A folder of finished Scratch or Python files from September to June shows growth far better than a single mark.

## Four stages of an elementary coder

Our own stages, drawn from teaching young children their first lines of code. Grade level and stage often differ, and that is fine.

**Stages of a young coder in the Ontario grades (ours)**

| Stage | What it looks like |
|---|---|
| 1. Follower | Builds a script by copying a model, block by block, and is delighted when it runs |
| 2. Fixer | Spots the wrong step in someone else&rsquo;s sequence and corrects it |
| 3. Predictor | Says what a loop or condition will do before running it, and is right more often than not |
| 4. Designer | Starts from a math question, plans the code, and explains why it works |

### For parents

Watch for stage 2 at home. A child who says &ldquo;that block is in the wrong place&rdquo; has moved past copying, whatever their grade.
Stage 3 is the one that the C3.2 expectations reward, and it grows only with practice at predicting, not with more screen time.

### For young coders

Before you press the green flag, say out loud what you think will happen.
When something goes wrong, change one block, then test. Not three blocks. One.

## Coding in Ontario elementary math: common questions

### Is coding part of the Ontario math curriculum?

Yes. The 2020 Ontario elementary mathematics curriculum includes coding in Strand C, Algebra, as overall expectation C3, in every grade from 1 to 8. Students are expected to solve problems and create computational representations of mathematical situations using coding concepts and skills.

### What is the Grade 1 coding expectation in Ontario?

Grade 1 C3.1 asks students to solve problems and represent math situations by writing and executing code that involves sequential events, meaning instructions carried out in order. C3.2 asks them to read and alter existing code with sequential events and describe how the changes affect the outcome.

### What is the Grade 3 coding expectation in Ontario?

Grade 3 C3.1 asks for code that involves sequential, concurrent and repeating events. Repeating events are loops, which the curriculum notes say make code more readable and reduce the number of instructions that need to be written.

### What is the Grade 6 coding expectation in Ontario?

Grade 6 C3.1 asks students to write and execute efficient code that involves conditional statements and other control structures. Grade 6 C3.2 adds that students describe how changes to the code affect both the outcomes and the efficiency of the code.

### What changes in Grades 7 and 8?

Grade 7 C3.1 adds events influenced by a defined count or a subprogram, which means loops that run until a condition is met and reusable pieces of code. Grade 8 C3.1 focuses on code that analyses data in order to inform and communicate decisions.

### Does the curriculum say which coding program to use?

No. The notes say coding can combine pseudocode, block-based coding programs and text-based coding programs, and that students can program a character on a screen, a classmate acting out the code, or a device such as a robot. Neither Scratch nor Python is named in the grade documents we read.

### My child has never coded. Is it too late in Grade 5?

No. Each year's expectation includes the earlier ideas, so a Grade 5 child starts with sequence and loops in the first weeks and reaches conditional statements quickly. Children who start later often move fast because their reading and math are stronger.

### Can I help with coding if I cannot code myself?

Yes. Ask your child to predict what their program will do before running it, change one number together and talk about what changed, and ask what the code is calculating. None of that needs any coding knowledge.

### Is coding tested on the EQAO assessments?

EQAO describes its Grade 3 and Grade 6 assessments as covering reading, writing and mathematics. We have not found an EQAO statement on whether coding questions appear, so we do not claim either way. Ask your school how coding is assessed in class.

### Do you use AI tools with young children?

Not to write their code. In these lessons the child writes every line, in unplugged activities, Scratch and then Python, and we use no chatbots or AI code generators with elementary students. Some of our kids' courses do teach what AI is by having children train small models of their own, with no chatbot accounts.
