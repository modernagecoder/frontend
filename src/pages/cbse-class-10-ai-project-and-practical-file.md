> Part C of CBSE Class 10 AI (417) is worth 50 marks and is conducted by the school before the theory paper: a practical file with a minimum of 15 programs (15 marks), a practical examination on Units 4 to 7, Statistical Data, Computer Vision, NLP and Advance Python (15), a viva (5), a project, field visit or student portfolio related to the Sustainable Development Goals (10), and a viva on that project (5). The file is built best at one program a week from the first month, the project is chosen in the first term and documented through the six stages of the AI project cycle, and both vivas are won by students who can explain their own choices. Modern Age Coders runs all of it inside the Monday and Wednesday 9 PM batch, closing the file and project by December.

## The five components and what each is judged on

The practical file (15): correct programs with their real outputs, indexed, in the school's format, evidently the student's own; lost to copied files whose outputs do not match the code. The practical examination on Units 4 to 7 (15): an unseen task in Python or Orange, solved and shown running under time; lost by students who rehearsed reproduction. The viva (5): whether the student understands the programs in their own file. The project, field visit or portfolio (10): a documented AI project cycle on a problem linked to the Sustainable Development Goals; lost to projects too big to finish, with no goal link or no evaluation numbers. The project viva (5): whether the student made the decisions and can defend them. Every component is lost the same way, through work the student did not really do.

## The file: eighteen entries, one anatomy

Each entry: serial number and date matching the index; the aim in one sentence; the program as it ran with a comment per block; the real output, which for charts and images means the picture; and a one-line remark. Built by month: April to May, set-up, add two lists, mean, median and mode with NumPy; June to July, line chart, scatter chart, bar chart, marks dictionary, CSV first ten rows; August to September, CSV information, CSV filter, statistics report, display an image, image shape; October to November, grayscale image, bag-of-words counter, train-test split by hand, accuracy calculator, menu program; December, index, formatting, every output re-checked, file closed. A file built in Jupyter, where output sits under code, cannot ship a mismatched output by accident.

## The project: six stages, one goal

1. Problem scoping with the 4Ws canvas, who, what, where, why, and the Sustainable Development Goal named here, not on the last page. Waste-photo sorting serves responsible consumption; rainfall and crop data serve zero hunger; sentiment on park reviews serves sustainable cities.
2. Data acquisition with the source written down: an open dataset with its origin, or a small dataset the student gathered.
3. Data exploration with a chart or two the student can read aloud, in Orange or Matplotlib.
4. Modelling in the tool that fits the student: a classifier in Orange, following CBSE's own Palmer penguins sample, or a few lines of Python, with the model type justified in Unit 2 vocabulary.
5. Evaluation with real numbers: accuracy, and for a classifier the confusion matrix with precision and recall, plus what the model gets wrong.
6. Reflection and the report: the six stages in order, a few pages, scoped in September, reviewed monthly, finished in December.

## The viva, two ways

Same waste-sorting classifier, same 92 percent accuracy. The viva that loses marks: "it was on a list", "92 percent is high", "it gets nothing wrong". The viva that earns them: the school bins mix plastic and paper and SDG 12 is responsible consumption; the confusion matrix shows foil confused with paper, so recall on foil is only 70 percent; the model gets shiny paper wrong and the next step is more foil photos. Three answers, three decisions, and the habit behind it is explaining every program aloud in one sentence every week.

## The practical examination

An unseen task on Units 4 to 7: a Python program from the suggested family with a twist, or an Orange task from the Statistical Data, Computer Vision or NLP practicals. From the second term, one Wednesday a month is a timed mock with the camera on, reviewed line by line, and a December dress rehearsal runs the whole practical day once: file checked, project demoed and questioned, a timed task, a viva with an unfamiliar teacher.

## Six mistakes seen every year

Outputs that do not match the code; np.mode, which does not exist; a project scoped for a company; the goal added on the last page; evaluation with no numbers; everything left to January, which steals the weeks the 21-mark theory units needed.

## Frequently asked questions

**Who conducts the practical?** The school, before the theory paper, on the Part C scheme; finish everything by December.

**Can the project be in Orange?** Yes; CBSE's own sample project is an Orange case study, and the marks are for the documented cycle and the defence, not the tool.

**Field visit or portfolio instead?** Allowed, any one of the three; most students choose the project because it is controllable and defensible.

**Must it link to the SDGs?** Yes, explicitly, in the problem scoping stage.

**Handwritten or printed file?** The school decides; the entry anatomy does not change.

**What does the viva ask?** File viva: what a line does and what changes with a different input. Project viva: why this goal, data, model, and what the evaluation number means.

**File behind?** Recoverable before November with someone checking each entry; from December, one to one.
