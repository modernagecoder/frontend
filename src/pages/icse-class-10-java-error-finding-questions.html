Ans. The short version

Find the error questions in ICSE Class 10 Computer Applications give a short Java fragment with one mistake and ask you to identify it, classify it and correct it. There are three kinds. A syntax error breaks the rules of Java, so the compiler refuses the program. A runtime error compiles but stops the program while it runs, such as division by zero or an index out of bounds. A logical error compiles and runs but gives the wrong answer. Modern Age Coders drills all three live in a Tuesday and Wednesday mini batch in India, or personalised one to one.

Q1. What are syntax, logical and runtime errors in Java?

Syntax, logical and runtime errors in ICSE Java, side by side

A syntax error is caught by the compiler, a runtime error is caught by Java while the program runs, and a logical error is caught by nobody except the person who checks the answer. That one sentence classifies every snippet on this page.

How to classify an error in three questions

  1. Would javac accept every line?

    Check semicolons, brackets, the types on both sides of each =, the spelling and case of names, and that every variable is declared and set before use. If a line fails, it is a syntax error.

  2. Could any line crash with legal code?

    Look for an int divided by something that can be 0, an index that can reach the length, a parse method or nextInt fed text, or a null String. If so, it is a runtime error.

  3. Does it give the answer the question wanted?

    Dry run it with small input whose answer you know. If the output differs, it is a logical error; name the line and the wrong idea.

A fragment that compiles and runs correctly belongs to a different question shape, tracing, covered on ICSE Java output questions.

Q5. How do you answer "correct the code" in the exam?

Correct the code ICSE Java: rewriting a program that has one bug

Write the corrected line in full, name the error type in one word, and give a one-line reason. Rewriting the whole program wastes time unless the question asks for it. Here are two Section B style methods, each with one bug, the way they come up in class.

Quote the line, then rewrite it

Copy the faulty line exactly, write "should be", then the corrected line. The examiner sees at once that you found the right line and fixed it the right way.

Name the type in one word

Syntax, runtime or logical. If the question asks which type, a correct fix with no label can still lose the mark.

Fix the cause, not the symptom

For snippet 23 the cause is the <= in the loop test. Wrapping the addition in a check on i hides the crash but leaves the wrong loop in place.

Test with input that can expose the bug

Try zero, a negative number, the first and last positions, and an input whose answer you know. Bugs live at the edges.

Questions about error finding

What students ask about find the error questions in ICSE Java

What are the three types of errors in Java for ICSE Class 10?

Syntax errors, runtime errors and logical errors. A syntax error breaks the grammar of Java, so the program does not compile. A runtime error compiles but stops the program while it runs, for example dividing an int by zero. A logical error compiles and runs to the end but produces a wrong result because the idea in the code is wrong.

What is the difference between a syntax error and a logical error?

A syntax error is found by the compiler before the program runs, and it comes with a message and a line number. A logical error is invisible to the compiler and to Java: the program runs normally and prints an answer, just the wrong one. You find a logical error only by checking the output against an answer you already know.

Is division by zero a syntax, runtime or logical error?

For int values it is a runtime error. The code compiles, then Java stops with ArithmeticException: / by zero when the line runs. The same happens with the % operator. With double values there is no crash: Java prints Infinity or NaN, so if the program should have refused that input, the mistake is logical.

Is a missing semicolon a syntax error?

Yes. javac reports "';' expected" and points to the end of the line where the semicolon belongs. The program cannot run until it is fixed. Note the opposite case too: an extra semicolon straight after if (...) or for (...) compiles happily and becomes a logical error.

Is an infinite loop a runtime error or a logical error?

An infinite loop is a logical error. The code is legal and Java does not throw any exception; the loop simply never reaches its exit because the update moves the variable the wrong way or never changes it. You notice it only because the program never finishes, so you trace the loop variable to find the fault.

Is ArrayIndexOutOfBoundsException a runtime error?

Yes. Using an index below 0 or equal to or above the array length compiles without complaint, but Java throws ArrayIndexOutOfBoundsException when that line runs, with a message such as "Index 5 out of bounds for length 5". The usual cause is a loop test that says "less than or equal to length" where it should say "less than length".

How do I write the answer to a correct the code question in ICSE?

Quote the faulty line, write the corrected line next to it, and name the error type if asked. Add one short reason, such as "a char literal needs single quotes". Rewrite the full program only when the question says so. Make one change per error, since examiners look for the specific line that was wrong.

Is using == to compare Strings an error in Java?

It compiles and runs, so it is not a syntax or runtime error, but it usually gives the wrong answer, which makes it a logical error. == checks whether two variables point to the same String object, not whether they hold the same characters. Use equals, or equalsIgnoreCase when case should not matter.

Are find the error questions asked in the ICSE Computer Applications paper?

Questions asking students to name the type of an error, or to correct a faulty statement, have appeared in Section A of past ICSE Computer Applications papers, as one-mark or two-mark parts. Section B rewards the same skill indirectly, because a program with a bug in it loses marks for the wrong output.
