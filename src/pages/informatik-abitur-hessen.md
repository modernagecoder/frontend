## Warum liefert SQL mehr Zeilen als die Relationenalgebra?

Relationenalgebra und SQL stehen in Hessen nebeneinander im Prüfungsstoff. Die folgende Aufgabe ist unsere eigene, keine echte Prüfungsaufgabe; Namen und Daten sind erfunden.

**Aufgabe (unsere).** In der Schulbücherei werden Ausleihen als Paare (Name, Genre) erfasst: (Mara, Krimi), (Mara, Comic), (Jonas, Krimi), (Lea, Sachbuch), (Jonas, Krimi), (Lea, Comic). a) Geben Sie das Ergebnis der Projektion auf das Attribut Genre an. b) Wie viele Zeilen liefert SELECT genre FROM ausleihe, und wie viele mit DISTINCT? c) Erklären Sie den Unterschied und was er für die Erfassung bedeutet.

**Lösung zu a) und b) (unsere)**

| Ausdruck | Anzahl | Ergebnis |
|---|---|---|
| Projektion auf Genre (Relationenalgebra) | 3 | Comic, Krimi, Sachbuch |
| SELECT genre FROM ausleihe | 6 | Krimi, Comic, Krimi, Sachbuch, Krimi, Comic |
| SELECT DISTINCT genre FROM ausleihe | 3 | Comic, Krimi, Sachbuch (sortiert) |

**Zu c).** Eine Relation ist eine Menge von Tupeln. Mengen enthalten kein Element doppelt, deshalb liefert die Projektion jedes Genre nur einmal. SQL arbeitet dagegen mit Tabellen, in denen Zeilen mehrfach vorkommen dürfen; erst DISTINCT entfernt Duplikate. Es gibt noch eine zweite, feinere Beobachtung: Das Paar (Jonas, Krimi) steht zweimal in der Liste. Als Relation aufgefasst wären das nur fünf verschiedene Tupel, nicht sechs. Für eine Bücherei, die jede Ausleihe zählen will, fehlt also ein Attribut, zum Beispiel ein Datum oder eine Ausleihnummer als Primärschlüssel.

**projektion.py: Menge gegen Tabelle** (Python)
```python
import sqlite3

ausleihe = [
    ("Mara", "Krimi"), ("Mara", "Comic"), ("Jonas", "Krimi"),
    ("Lea", "Sachbuch"), ("Jonas", "Krimi"), ("Lea", "Comic"),
]

# Projektion in der Relationenalgebra: Ergebnis ist eine Menge
projektion = {genre for name, genre in ausleihe}
print("Relationenalgebra:", sorted(projektion), len(projektion))
print("Tupel als Menge:", len(set(ausleihe)), "statt", len(ausleihe))

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE ausleihe (name TEXT, genre TEXT)")
db.executemany("INSERT INTO ausleihe VALUES (?, ?)", ausleihe)
ohne = db.execute("SELECT genre FROM ausleihe").fetchall()
mit = db.execute("SELECT DISTINCT genre FROM ausleihe ORDER BY genre").fetchall()
print("SQL ohne DISTINCT:", len(ohne), "Zeilen")
print("SQL mit DISTINCT:", [z[0] for z in mit], len(mit))
```
Ausgabe, von uns ausgeführt: Relationenalgebra: ['Comic', 'Krimi', 'Sachbuch'] 3, Tupel als Menge: 5 statt 6, SQL ohne DISTINCT: 6 Zeilen, SQL mit DISTINCT: ['Comic', 'Krimi', 'Sachbuch'] 3.

Python bildet die Projektion mit einer Menge nach, die SQL-Abfragen laufen in einer kleinen SQLite-Datenbank im Arbeitsspeicher. In der Prüfung schreiben Sie beides von Hand. Den Code nutzen wir in der Vorbereitung nur, um eine Lösung hinterher zu überprüfen.

1. **Erst die Anzahl schätzen.** Sagen Sie vor jeder Abfrage voraus, wie viele Zeilen herauskommen. Weicht das Ergebnis ab, haben Sie etwas über die Daten gelernt.
2. **Menge oder Tabelle?** Fragen Sie bei jeder Lösung, ob Sie in Relationenalgebra (ohne Duplikate) oder in SQL (mit Duplikaten) denken.
3. **Doppelte Zeilen sind ein Hinweis.** Zwei gleiche Datensätze deuten oft auf einen fehlenden Schlüssel hin. Das ist genau der Übergang zum ER-Modell.
