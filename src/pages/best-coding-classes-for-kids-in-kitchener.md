## Grade 7: when a Kitchener student&rsquo;s code is built from reusable pieces

Kitchener schools teach the Ontario curriculum. Grade 7 math brings in sub-programs, the pieces most languages call functions. We read the wording from the ministry&rsquo;s curriculum data on 22 October 2026; the quotes are the ministry&rsquo;s and the reading is ours.

- **C3.1**: Code &ldquo;that involves events influenced by a defined count and/or subprogram and other control structures&rdquo;. Our answer: A defined count is a loop that runs a set number of times. A subprogram is a named block of code that does one job.
- **Note**: The ministry adds that sub-programs can be reused, or called more than once from one main program, and gives the example of a sub-program for the area of a rectangle. Our answer: Write it once, use it many times. This is the single biggest step from beginner code to real code.
- **Feelings**: A student voice in the curriculum says: &ldquo;I need to stay calm, knowing that we may have to make a few tweaks before we get it right.&rdquo; Our answer: The ministry expects frustration. A good class plans for it, and celebrates the fix.
- **Grade 8**: The next year asks for code involving &ldquo;the analysis of data in order to inform and communicate decisions&rdquo;. Our answer: Which is what the playground project below is: data, checked, then turned into a careful sentence.

Here is the ministry&rsquo;s rectangle idea as a Python function, written by us. It is defined once and then used twice: first for the area of a 6 by 4 rectangle, then inside the volume of a box 10 units tall. It prints 24 and then 240:

```
def rectangle_area(length, width):
    return length * width

print(rectangle_area(6, 4))
print(rectangle_area(6, 4) * 10)
```

## A playground installed in 3013? Checking dates in the City of Kitchener file

The City of Kitchener publishes its playgrounds as open data, with a construction year and an installation date for each. Children in our classes, usually from about age 10, check those two columns before trusting either. Every figure here is our count, not the City&rsquo;s.

**Our check of the CONSTRUCTION_YEAR and INSTALLATION_DATE columns in the City of Kitchener Playgrounds CSV, downloaded 22 October 2026 (337 rows)**

| What we found | Rows |
|---|---|
| CONSTRUCTION_YEAR left blank | 92 |
| CONSTRUCTION_YEAR written as the word PRE | 72 |
| CONSTRUCTION_YEAR usable as a number (1998 to 2024) | 173 |
| No INSTALLATION_DATE at all | 240 |
| INSTALLATION_DATE in the year 3013, on a row built in 2013 | 1 |
| Rows with both a numeric year and a date that agree on the year | 48 of 77 |
| Rows where installation comes before construction | 9 |

Our checker uses only the standard library. Each row is sorted into blank, PRE, future or usable, and any installation date after this year is printed for a human to look at:

```
import csv

this_year = 2026
problems = {"blank": 0, "PRE": 0, "future": 0}
good = []
with open("Playgrounds.csv", encoding="utf-8-sig") as f:
    rows = csv.DictReader(f)
    for row in rows:
        year = row["CONSTRUCTION_YEAR"].strip()
        if year == "":
            problems["blank"] += 1
        elif year == "PRE":
            problems["PRE"] += 1
        elif int(year) > this_year:
            problems["future"] += 1
        else:
            good.append(int(year))
        installed = row["INSTALLATION_DATE"][:4]
        if installed and int(installed) > this_year:
            print("impossible:", row["INSTALLATION_DATE"][:10], "built", year)

print(problems)
print(len(good), "usable years, from", min(good), "to", max(good))
```

On our download it prints one impossible date, 3013/06/18, on a playground built in 2013, then the problem counts, then &ldquo;173 usable years, from 1998 to 2024&rdquo;.

### A typo, almost certainly

3013 sits next to a construction year of 2013, so a mistyped first digit is the likely story. But it is our guess, and a careful report says so instead of silently changing it to 2013.

### What PRE probably means

Seventy-two rows say PRE instead of a year. The file does not define it. It may mean built before records began, but we do not know, so the script keeps those rows out of any average.

### Two dates, two meanings

Nine rows show installation before construction. Perhaps the two columns record different things, such as equipment and the site. That is a question for the City, not something to fix in code.

### A file that changes daily

The City describes the layer as updated daily, and it asks users to check each record&rsquo;s CREATE_DATE and UPDATE_DATE. On 22 October 2026 the portal&rsquo;s CSV had 337 rows while the live map service reported 340. Students learn to write which copy they used and when.

## Would an AI tool have noticed the year 3013?

Perhaps. It might also have quietly averaged it in.

Hand the Kitchener playgrounds file to an AI tool and ask for the average construction year, and it may skip the PRE rows, treat blanks as zero, or not mention the 3013 date at all. The number it prints will look reasonable either way. A student who has written the checker knows exactly which rows were left out and why, and can say so.

That is the habit we teach children: check the data, decide the rules, write the code, and explain the result in a sentence that is true. Our classes cover how AI works and where it goes wrong, but children do their own reasoning. At home, OpenAI requires a parent&rsquo;s permission for ChatGPT users under 18.

Ontario&rsquo;s Grade 8 expectation is about using data to inform decisions; a decision built on an unchecked 3013 is not informed. The longer argument is in [our case for learning to code in 2026](/blog/is-coding-worth-learning-2026).
