**Where can a Guelph teenager learn Python, data and AI with a live teacher?** Modern Age Coders teaches Python and AI to Guelph students between 13 and 18 in live online classes, in groups of fifteen to twenty or one to one. The usual start is Python for Teens; after that, students choose AI and Machine Learning for Teens, CCC preparation, or the Ontario Computer Science Companion beside ICS3U and ICS4U. Every class runs on Eastern time, and the first is free.

In Ontario, data arrives in a student&rsquo;s coding before most families notice. The Grade 8 math curriculum already asks for code that analyses data, Grade 9 math pairs code with algebra, and the senior computer science courses add software design and the place of computers in society. For a Guelph teenager that is a good thread to pull on, because the most useful skill in modern AI is not writing a prompt but working out what a column of numbers can and cannot tell you. ## The data thread in Ontario coding, from Grade 8 math to ICS4U

Quoted text: the Ontario curriculum service and the 2008 computer studies document, both checked on 22 October 2026. Right-hand notes: ours.

**Coding and data in Ontario courses a Guelph teen meets (Ontario Ministry of Education curriculum API and 2008 computer studies document, checked 22 October 2026)**

| Grade and course | Ministry wording | Our note |
|---|---|---|
| Grade 8 math, C3.1 | Students code &ldquo;including code that involves the analysis of data in order to inform and communicate decisions&rdquo; | A 13 year old is already expected to use code to reason about data |
| Grade 8 math, C3.2 | Students &ldquo;read and alter existing code involving the analysis of data in order to inform and communicate decisions&rdquo; | Reading someone else&rsquo;s analysis and changing it, a real-world skill |
| Grade 9, MTH1W, C2.1 | Students &ldquo;use coding to demonstrate an understanding of algebraic concepts including variables, parameters, equations, and inequalities&rdquo; | Variables in code and variables in algebra, taught as one idea |
| Grade 10, ICD2O (2023) | Strands titled &ldquo;Computational Thinking and Making Connections&rdquo;, &ldquo;Hardware, Software, and Innovations&rdquo; and &ldquo;Programming&rdquo; | Broad by design: thinking, technology and code in one course |
| Grades 11 and 12, ICS3U and ICS4U (2008) | Each course opens with Programming Concepts and Skills and Software Development; &ldquo;The fourth strand (strand D) deals with the role of computers in society&rdquo; | Building software and asking what it does to people, both on the syllabus |

Notice how often the word data appears before Grade 11. The Grade 8 expectations do not ask students to analyse data by hand and then learn to code separately; they ask for code that analyses data to support a decision. That is exactly the shape of a small machine learning task, and it is why our Guelph students meet real public datasets early. There is also a small curriculum change families sometimes ask about: the 2008 document still describes a Grade 10 course, ICS2O, that is &ldquo;organized in three strands&rdquo;, but the current ministry list of computer studies courses does not include ICS2O and does include ICD2O. We state both facts and leave the history to the ministry; the practical point is that ICD2O is the Grade 10 course on today&rsquo;s list.

### Grade 8: real files early

We give Grade 8 students a small real table, ask a question it can answer, and have them write the code that answers it. The decision part matters: what would you do differently because of this number?

### Grades 9 and 10: algebra meets code

### Grades 11 and 12: the society strand

Strand D asks about computers in society. AI gives that question plenty to work with, and our older students write short, evidence-based notes on what a model they built could get wrong.

## Can a simple model forecast Guelph&rsquo;s green bin volume a year ahead?

The City of Guelph publishes the monthly volume of organic waste collected through its green bin program from 2012 to 2019. Our students clean the table, then forecast every month of 2019 from earlier years and check how far off each forecast is. All results here are our own calculations; the volumes are the City&rsquo;s, in the units it published, which the dataset does not state.

**Our forecasts of the 12 months of 2019 on the City of Guelph Total Organic Waste Volume by Month 2012_2019 file (96 monthly rows fetched 22 October 2026)**

| Forecast method | How it guesses a 2019 month | Average miss per month |
|---|---|---|
| Flat average | The 2018 monthly average, for every month | 98.2 |
| Same month last year | The value for the same month in 2018 | 38.5 |
| Same month, six-year mean | The average of that month from 2013 to 2018 | 51.4 |

The code below uses nothing beyond Python&rsquo;s standard library, and most of it is cleaning: the year appears only on each January row, so the code carries it forward, and the month names arrive in several spellings with stray spaces, so the code trims and shortens them. Only then does it forecast. Run on 22 October 2026, it printed the three averages shown above:

```
import json, urllib.request

URL = ("https://services5.arcgis.com/k3dd78JyG9GFoZHG/arcgis/rest/services/"
       "CoG_Org_Waste_Month_Vol_2012_2019/FeatureServer/0/query"
       "?where=1%3D1&outFields=*&orderByFields=ObjectId&f=json")
rows = [f["attributes"] for f in json.load(urllib.request.urlopen(URL))["features"]]

# The year is filled in only on each January row, and month names are typed
# inconsistently ("Feb ", "April", "Sept "), so clean both before anything else.
volume, year = {}, None
for r in rows:
    year = r["Year"] or year
    volume[(year, r["Month"].strip()[:3].title())] = r["Volume"]

MONTHS = ["Jan", "Feb", "Mar", "Apr", "May", "Jun",
          "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]
print(len(rows), "rows,", len(volume), "year-month cells,",
      min(y for y, m in volume), "to", max(y for y, m in volume))

def miss(guess):
    return round(sum(abs(guess(m) - volume[(2019, m)]) for m in MONTHS) / 12, 1)

last_year = sum(volume[(2018, m)] for m in MONTHS) / 12
print("flat 2018 monthly average:", miss(lambda m: last_year))
print("same month in 2018:", miss(lambda m: volume[(2018, m)]))
print("same month, mean of 2013-2018:",
      miss(lambda m: sum(volume[(y, m)] for y in range(2013, 2019)) / 6))
lowest = [min(MONTHS, key=lambda m: volume[(y, m)]) for y in range(2012, 2020)]
print("lowest month each year, 2012-2019:", lowest)
```

### 1. Clean like a spreadsheet

The table looks like a copied spreadsheet: a year written once, then blanks, and month labels typed sixteen different ways, such as &ldquo;Aug&rdquo; and &ldquo;Aug &rdquo; with a trailing space. Students who skip this step get twelve months that do not line up.

### 2. The seasonal naive baseline

Guessing that a month will look like the same month last year is called a seasonal naive forecast, and it is the baseline every serious forecaster tries first. Here it beats both alternatives: an average miss of 38.5 against 51.4 and 98.2.

### 3. Why the long average loses

A six-year mean should be steadier, yet it does worse. In 10 of the 12 months the 2018 value is higher than the 2013 value, so the older years drag the mean down. Recent data wins when a series is trending, an idea students test by trying three-year and two-year means.

### February and the calendar

February has the lowest total in every year from 2013 to 2019. That looks like a pattern in behaviour until a student divides by the number of days: per day, February is the lowest month only in 2014, 2015 and 2019. Most of the dip is simply a shorter month. Turning totals into per-day rates is a first taste of feature engineering, choosing what to measure so that a model learns the right thing.

A few more honest details. The program began in 2012, and January 2012 shows 74.33 against 256.67 in February, so the first months describe a launch rather than normal service, which is why the six-year mean starts at 2013. The same-month model&rsquo;s biggest misses on 2019 were April, 81.5 too low, and August, 73.3 too high. The City notes that the figures do not include organic waste collected in Waterloo Region and processed at the Guelph Waste Resource Innovation Centre, so this is Guelph&rsquo;s own green bin collection only. We never add the monthly rows into yearly totals; the City publishes a separate yearly file for that. The data is used under the City of Guelph&rsquo;s Open Data Licence Version 2.0, which grants a licence &ldquo;to use the Information including for commercial purposes&rdquo;, and attribution goes to the City of Guelph under its Open Government Licence. No endorsement by the City of Guelph is implied.

## Why a Guelph teen should beat a simple baseline before reaching for AI

Because &ldquo;same month last year&rdquo; beat two more elaborate guesses, and only a student who tried it would know.

Forecasting is full of clever methods that lose to a plain baseline. A teen who has watched a six-year average lose to last year&rsquo;s value understands something many adults do not: complexity is not accuracy, and every model has to earn its place against the simplest reasonable guess.

We teach in that spirit. State the question, clean the data, try the obvious answer, then try to beat it, and explain why the winner won. AI tools can join later, inside the age rules, as a reviewer whose suggestions are tested like any other model. Students who learn this way can tell a good result from a lucky one.

On CCC day there is no assistant at all, so the reasoning has to be the student&rsquo;s from the first line. The longer argument is in [an argument for learning to code in 2026](/blog/is-coding-worth-learning-2026).
