## Al Khuwair data project: unique visitors are not visits

The assigned Al Khuwair project uses a synthetic event log. It does not monitor the square, walkway, theatre, schools, college, ministries or any other real place. No personal data is collected.

The practice file contains 15 event rows. The invented token `AK-04` appears 11 times. Four other tokens, `AK-12`, `AK-19`, `AK-23` and `AK-31`, appear once each.

```python
events = ["AK-04"] * 11 + [
    "AK-12", "AK-19", "AK-23", "AK-31"
]

visits = len(events)               # 15
unique_visitors = len(set(events)) # 5
repeat_visits = visits - unique_visitors # 10
```

Counting every row produces 15 visits. Counting distinct tokens produces 5 unique visitors. Calling the first number 15 people would count one repeat token as eleven people.

The code is easy. The measurement definition is the real work. A learner must state:

1. whether the question is about activity, people, repeat use or reach;
2. what creates and expires an identifier;
3. the beginning and end of the reporting window;
4. how missing identifiers and automated traffic are treated;
5. whether the result means visits, devices, accounts, tokens or people.

If the identity rule is unknown, the honest label is distinct tokens, not distinct people. A learner can then test how resetting a token or using two devices changes the number without changing the human being. Older learners can compare cookies, logins and device identifiers. Younger learners can sort coloured identifier cards by hand before coding the same operation with a set.

The project deliberately refuses to estimate real Al Khuwair footfall. If a learner later receives a legitimate dataset, privacy, purpose, retention and access controls must be agreed before analysis.
