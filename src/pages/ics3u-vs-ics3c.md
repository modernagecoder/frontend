# ICS3U vs ICS3C: which Grade 11 computer course fits?

Every Ontario student who wants computer studies in Grade 11 meets the same fork in the course calendar: ICS3U, the university preparation course, or ICS3C, the college preparation course. The names sound alike and both teach programming, so families often pick on a guess. This page sets the two side by side on twelve points taken from the curriculum itself, shows one task of each kind in Python and Java, and gives a short way to decide. ### What the two have in common

Much of the course is shared. Both ask for user input, processing and screen output; both use sequence, selection and repetition; both ask students to correct syntax, logic and run-time errors and to test their programs against a test plan. Both apply the same seven-phase software development life cycle to a project.

So an ICS3C class is not a lighter copy of ICS3U. It is a programming course with its own focus, and a student who does well in it has learned to write, test and fix real programs.

### Where the real gap is

The gap is clearest in rows 3 and 7. ICS3U students spend weeks on arrays: storing a list of values, searching it, inserting into it and deleting from it. ICS3C students spend that time on making a program robust: checking what a user typed, counting and totalling, and handling a run-time error without crashing.

Row 1 explains why. The curriculum says college preparation courses aim at challenges &ldquo;such as creating custom programs, tailoring existing program packages, and using database management systems and scripting languages&rdquo;. That is a practical brief, and a good one for the right student.

Source: [The Ontario Curriculum, Grades 10 to 12: Computer Studies (2008)](https://www.edu.gov.on.ca/eng/curriculum/secondary/computer10to12_2008.pdf), the program overview, the course table and the ICS3U, ICS3C, ICS4U and ICS4C course pages, read 22 October 2026. ## One ICS3C-style task and one ICS3U-style task, in Python and Java

Expectations are easier to compare as programs. We wrote one task in the spirit of each course, using examples the curriculum itself lists: fuel consumption on a car trip for ICS3C, and adding data to a sorted array for ICS3U. Neither is from any school&rsquo;s course; all four programs were run.

Task C, the ICS3C kind. Ask for the distance of a trip in kilometres and the fuel used in litres, refuse anything that is not a sensible number, then print the fuel use in litres per 100 km and a one-word rating. The hard part is not the formula. It is the program&rsquo;s behaviour when the user types four hundred, or a negative number.

**Python · Task C, fuel use with checked input (ours)** (python)
```python
# Fuel use for a car trip, with checked input (ours, an ICS3C-style task)

def read_number(prompt, low, high):
    """Keep asking until the user types a number from low to high."""
    while True:
        text = input(prompt)
        try:
            value = float(text)
        except ValueError:
            print("That is not a number. Try again.")
            continue
        if low < value <= high:
            return value
        print("Please type a number above", low, "and up to", high)


def litres_per_100_km(litres, km):
    return litres / km * 100


km = read_number("Distance driven in km: ", 0, 5000)
litres = read_number("Fuel used in litres: ", 0, 500)
rate = litres_per_100_km(litres, km)
print("Fuel use:", round(rate, 1), "L/100 km")
if rate < 6:
    print("Rating: efficient")
elif rate <= 10:
    print("Rating: typical")
else:
    print("Rating: thirsty")
```
Run with the inputs four hundred, -20, 412 and 31.5, it rejects the first two, then prints Fuel use: 7.6 L/100 km and Rating: typical. The try and except block is the run-time error handling the ICS3C expectations ask for.

**Java · Task C, fuel use with checked input (ours)** (java)
```java
// Fuel use for a car trip, with checked input (ours, an ICS3C-style task)
import java.util.Scanner;

public class Fuel {
    static Scanner in = new Scanner(System.in);

    // Keep asking until the user types a number above low and up to high.
    static double readNumber(String prompt, double low, double high) {
        while (true) {
            System.out.print(prompt);
            String text = in.nextLine().trim();
            try {
                double value = Double.parseDouble(text);
                if (value > low && value <= high) {
                    return value;
                }
                System.out.println("Please type a number above " + low + " and up to " + high);
            } catch (NumberFormatException e) {
                System.out.println("That is not a number. Try again.");
            }
        }
    }

    public static void main(String[] args) {
        double km = readNumber("Distance driven in km: ", 0, 5000);
        double litres = readNumber("Fuel used in litres: ", 0, 500);
        double rate = litres / km * 100;
        System.out.printf("Fuel use: %.1f L/100 km%n", rate);
    }
}
```
Same inputs, same result line. One small difference worth noticing: Java prints the limits as 0.0 and 5000.0 because they are doubles, where the Python version prints 0 and 5000.

Task U, the ICS3U kind. A list of marks is already sorted from low to high. Add a new mark so the list stays sorted, without calling a built-in sort or insert. The hard part is the shifting: every value larger than the new one moves one place to the right, starting from the end, and the new value drops into the gap.

**Python · Task U, insert into a sorted list (ours)** (python)
```python
# Add a value to a sorted list without sort() or insert() (ours, an ICS3U-style task)

def insert_sorted(values, new):
    """values is sorted from low to high. Return a new list with
    new placed so the order is kept."""
    result = values + [None]          # one extra slot at the end
    i = len(values) - 1
    while i >= 0 and result[i] > new:
        result[i + 1] = result[i]     # shift bigger values one place right
        i -= 1
    result[i + 1] = new               # the gap is where new belongs
    return result


marks = [52, 61, 70, 84, 93]
print(insert_sorted(marks, 77))
print(insert_sorted(marks, 40))
print(insert_sorted(marks, 99))
print(insert_sorted([], 5))
```
Prints [52, 61, 70, 77, 84, 93], then [40, 52, 61, 70, 84, 93], then [52, 61, 70, 84, 93, 99], then [5]. The last three lines test the edges: a new smallest value, a new largest value and an empty list.

**Java · Task U, insert into a sorted array (ours)** (java)
```java
// Add a value to a sorted array, keeping the order (ours, an ICS3U-style task)
import java.util.Arrays;

public class InsertSorted {

    // count says how many slots of values are in use; the array has room for one more.
    public static int insertSorted(int[] values, int count, int newValue) {
        int i = count - 1;
        while (i >= 0 && values[i] > newValue) {
            values[i + 1] = values[i];      // shift bigger values one place right
            i--;
        }
        values[i + 1] = newValue;           // the gap is where newValue belongs
        return count + 1;                   // one more slot is now in use
    }

    public static void main(String[] args) {
        int[] marks = new int[6];
        int[] start = {52, 61, 70, 84, 93};
        for (int k = 0; k < start.length; k++) {
            marks[k] = start[k];
        }
        int count = insertSorted(marks, 5, 77);
        System.out.println(Arrays.toString(Arrays.copyOf(marks, count)));
    }
}
```
Prints [52, 61, 70, 77, 84, 93]. A Java array cannot grow, so the program keeps a count of the slots in use: a pattern ICS3U Java classes meet often.

**The two tasks compared (ours)**

|  | Task C (ICS3C kind) | Task U (ICS3U kind) |
|---|---|---|
| Main skill | Checking input and handling errors | Moving data inside an array |
| Where students slip | Forgetting the user can type anything | Shifting from the front and overwriting values |
| Edge cases to test | Text, zero, a negative, a huge value | Smallest, largest, empty list |
| Typical bug | A crash on bad input | An index one past the end |
| Closest real job | A form or a till that must not crash | Keeping a leaderboard in order |

### What a student learns from trying both

Students who enjoy Task U, where the challenge is in the logic of the data, tend to enjoy the direction ICS3U and then ICS4U take: searching, sorting, recursion and analysing algorithms.

Students who enjoy Task C, where the challenge is making a program behave well for a real person, often enjoy the direction ICS3C and ICS4C take: object-oriented programs with graphical interfaces, data validation and projects that look like workplace software.

### Both tasks start the same way

Before any code, we ask students to write three lines: what goes in, what the program does with it, and what comes out. Both curriculum courses name this input-process-output model, and it is the step that turns a vague task into a plan.

Then they list the test cases before running anything. For Task C the list starts with text where a number should be. For Task U it starts with an empty list. Writing those down first is the habit we care about most in either course.

## How to choose between ICS3U and ICS3C, in five steps

The curriculum&rsquo;s own advice is short: &ldquo;Students choose between course types on the basis of their interests, achievement, and postsecondary goals.&rdquo; These steps, which are ours, turn that sentence into questions a family can answer at the kitchen table. The school&rsquo;s guidance counsellor has the final word on any one student&rsquo;s timetable.

1. Name the destination, even roughly. If the plan is a degree in computer science, engineering or math, that points to ICS3U, because the university preparation course is the one designed to meet university entrance requirements and it is the only Grade 11 course that leads to ICS4U. A college program in programming, IT or a related trade points to ICS3C.
2. Check the Grade 12 course you will need. ICS4U lists ICS3U as its prerequisite, and ICS4C lists ICS3C. Choosing the Grade 11 course is also choosing which Grade 12 computer course is open next year.
3. Look at the math plan beside it. University computer science programs care most about Grade 12 math. A student on the Functions, Advanced Functions and Calculus and Vectors route is usually also on the U route in computer studies.
4. Be honest about interest, not only marks. A student who wants to know why an algorithm works will be happier in ICS3U. A student who wants to build something useful quickly may be happier in ICS3C, and will still write real code.
5. Ask about the school&rsquo;s offer. Each school decides which courses it runs and which language it teaches them in. The school course calendar and the counsellor say what is actually available.

**A quick self-check (ours; a starting point for a conversation, not a placement test)**

| If the student... | Lean toward |
|---|---|
| plans a university degree in computer science, engineering or math | ICS3U |
| wants ICS4U in Grade 12 | ICS3U |
| plans a college diploma in programming or IT, or an apprenticeship | ICS3C |
| enjoys puzzles about data and order, like Task U | ICS3U |
| enjoys making a program behave well for its user, like Task C | ICS3C |
| has not decided between college and university | A talk with the counsellor first: ICS3U opens only ICS4U and ICS3C opens only ICS4C, so this choice sets the Grade 12 option |

### A common worry: is ICS3U too hard to try?

The course table lists no prerequisite for ICS3U, which means a student with no coding background can enrol in it. The first unit is the same kind of programming in both courses, and the step up in ICS3U comes later, with arrays and subprograms.

What helps most is starting early. A student who has written a few small programs over the summer meets the array unit with confidence instead of panic. That is often where an outside teacher is most useful.

### A common mistake: choosing by the friend group

Students often take whichever course their friends picked. Computer studies is optional, and the Grade 11 choice shapes the Grade 12 choice through its prerequisite, so it is worth a ten-minute conversation about the destination first.

It is also worth remembering that a college preparation course is a real course with a real purpose. Students who take ICS3C because it fits their plans are not settling; they are choosing the course designed for where they are going.

### University, in the universities&rsquo; words

On 22 October 2026, the University of Waterloo&rsquo;s Computer Science page named ICS3U by its title as the recommended course for Ontario applicants: &ldquo;Grade 11 U Introduction to Computer Science&rdquo;. It is the U course, not the C course, that the page names.

The University of Toronto&rsquo;s Computer Science listings ask Ontario applicants for an OSSD with &ldquo;six subjects at the 4U/M level&rdquo;. ICS4C is a college preparation course, so on our reading it is not one of the 4U/M courses that line counts, while ICS4U is. Check each university&rsquo;s page in the year your teen applies.

### College and apprenticeship

For college, the 2008 document is clear about the purpose: the C courses are designed for entrance &ldquo;to most college programs&rdquo; and for apprenticeship and other training. Individual college programs set their own admission requirements, so a family should read the requirements of the programs they are considering.

If plans change after Grade 11, the prerequisite rule matters: a student who took ICS3C and later wants ICS4U needs ICS3U first, because that is the prerequisite the course table lists.

We spend the most time on making programs reliable: reading input safely, building test plans that include silly input, and finding the cause of a run-time error from its message. We also build small, practical programs the student cares about.

## ICS3U vs ICS3C: common questions

### What is the difference between ICS3U and ICS3C?

ICS3U, Introduction to Computer Science, is the Grade 11 university preparation course and leads to ICS4U. ICS3C, Introduction to Computer Programming, is the Grade 11 college preparation course and leads to ICS4C. ICS3U puts more weight on arrays and the theory behind programs; ICS3C puts more weight on practical, reliable programs.

### What is ICS3C?

ICS3C is Introduction to Computer Programming, Grade 11, College Preparation, described in Ontario's 2008 Computer Studies curriculum. Students write and test programs, learn program design, run a project with a software development life cycle, and study computer components, safe computing and careers.

### Does ICS3C have a prerequisite?

No. The 2008 curriculum lists no prerequisite for ICS3C or for ICS3U, and the current Ontario curriculum website shows none either.

### Can I take ICS4U after ICS3C?

Not directly. The prerequisite for ICS4U is ICS3U. ICS3C is the prerequisite for ICS4C, the Grade 12 college preparation course. A student who wants ICS4U after ICS3C should talk to the school counsellor about taking ICS3U first.

### Is ICS3C easier than ICS3U?

It is different rather than simply easier. ICS3C spends less time on arrays and more on input checking, counting, totalling and handling run-time errors. Both courses ask students to write, test and debug real programs.

### Which one do universities want for computer science?

On 22 October 2026, the University of Waterloo named Grade 11 U Introduction to Computer Science, which is ICS3U, as its recommended course for Computer Science. University computer science programs mostly require Grade 12 math and English; check each program's own page in the year you apply.

### Is ICS3C good for college programs?

The 2008 curriculum says college preparation courses are designed to help students meet the requirements for entrance to most college programs or for admission to apprenticeship or other training programs. Each college program sets its own admission requirements, so check the programs you are considering.

### Do you teach ICS3C as well as ICS3U?

Yes. We help students in either course, in the language their school uses, working from their own course outline and assignments.

### Do you grant the ICS3U or ICS3C credit?

No. Our classes are teaching and practice beside the school course, and we do not grant Ontario credits. The credit comes from the school or credit provider that teaches and evaluates the course.
