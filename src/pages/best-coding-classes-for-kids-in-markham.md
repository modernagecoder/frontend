## Loops inside loops, then code that decides: Grades 4 and 5 in Markham

Markham&rsquo;s public schools teach the Ontario curriculum. We took the Grade 4 and Grade 5 coding wording straight from the ministry&rsquo;s curriculum data on 22 October 2026. Quoted words belong to the ministry; the explanations are ours.

- **Grade 4**: Expectation C3.1 adds code with &ldquo;repeating, and nested events&rdquo;, and a teacher note explains that loops can sit inside other loops. Our answer: One loop draws a row; an outer loop repeats the row. The ministry&rsquo;s own example draws a square with &ldquo;Repeat 4 times: Move 100 steps. Turn 90 degrees.&rdquo;
- **Grade 5**: C3.1 moves on to code &ldquo;that involves conditional statements and other control structures&rdquo;. Our answer: An if statement: the program checks something and takes one path or another. This is where most children first feel that a program is thinking.
- **Grade 5 note**: The ministry calls conditional statements &ldquo;a representation of binary logic (yes or no, true or false, 1 or 0)&rdquo;. Our answer: Every if asks a yes-or-no question. Children who can say the question out loud write far fewer broken conditions.
- **Grade 5 examples**: Suggested tasks include code that would decide who can ride the roller coaster at an amusement park, and a guess-the-number game. Our answer: Both are favourites in our classes too, because a child can test them with their own numbers.

Two short programs, written by us, show each grade in typed Python. The first is a Grade 4 nested loop: the inner loop builds a line of four stars and the outer loop prints that line three times.

```
for row in range(3):
    line = ""
    for col in range(4):
        line = line + "*"
    print(line)
```

It prints three rows of four stars. The second is the Grade 5 ride check, with our own made-up height rule of 120 centimetres. With a height of 125 it prints &ldquo;You can ride&rdquo;; change the height to 110 and it prints &ldquo;Not yet&rdquo;.

```
height = 125
if height >= 120:
    print("You can ride")
else:
    print("Not yet")
```

### The edge case

Ask a child what happens at exactly 120. Many guess wrong, because the difference between greater-than and greater-than-or-equal is invisible until you test it. Testing the boundary is the most useful habit Grade 5 can build.

### Reading before running

Ontario also asks children to read and alter existing code and describe how a change affects the outcome. We do this every lesson: predict the output, run it, and explain any surprise.

## Seven signs of a strong kids&rsquo; coding class, visible in one trial lesson

Brochures look alike; lessons do not. These are the signs we would look for as parents, written for Markham families with a child aged 6 to 12. They are our own guide, and they apply to our trial lessons as much as anyone&rsquo;s.

**What to watch for in a free trial coding lesson for a child aged 6 to 12 (our guide, October 2026)**

| Sign | What you will see | What its absence looks like |
|---|---|---|
| The child talks more than once a minute | The teacher asks what the code will do, and waits for an answer. | A long demonstration while the child watches and nods. |
| Mistakes are treated as information | A bug becomes a question: what did you expect, and what happened? | The teacher quietly fixes it, or the child is told to copy again. |
| The task matches the grade | A Grade 4 child meets loops inside loops; a Grade 5 child meets if statements. | Every age gets the same drag-and-drop activity. |
| The child changes something | Before the end, the rule changes and the child adapts their own program. | The lesson ends the moment the copied program works. |
| The group is the right size for the age | The teacher can see each screen and names each child. | Children wait a long time with their hand up, or drift off camera. |
| You hear a plan | The teacher can say what the next few lessons build toward. | &ldquo;We&rsquo;ll see how it goes&rdquo; with no next step. |
| Your child leaves with something | A program they can run again at home and explain to you. | A certificate, but nothing they can show working. |

### If you can only watch five minutes

Watch for the first mistake. How a teacher handles one broken program tells you more than an hour of slides about the curriculum.

### Ask the same thing everywhere

Use one question at every trial: what will my child be able to build in eight weeks that they cannot build today? Compare the answers side by side.

### Then ask your child

On the drive home, ask which part was hard. A child who names a specific bug and how it was fixed has been taught, not entertained.

## How old are the buildings the City of Markham owns? A project in Python

The City of Markham publishes a file called City Owned Facilities, with the year each building was built. Our students aged about 10 to 12 sort the 82 rows into centuries with one line of integer division. All the counts here are ours.

**Our count of City Owned Facilities by type and by the hundred years the building dates from (City of Markham Open Data, downloaded 22 October 2026, 82 rows)**

| Type in the file | 1800s | 1900s | 2000s |
|---|---|---|---|
| Museum | 31 | 18 | 3 |
| Community Centre | 3 | 12 | 6 |
| Library | 1 | 2 | 0 |
| Recycling Depot | 1 | 2 | 0 |
| Art Gallery | 1 | 1 | 0 |
| Theatre | 0 | 1 | 0 |
| All 82 rows | 37 | 36 | 9 |

Our script, using only Python&rsquo;s standard library. The key line is hundreds = year // 100 * 100: dividing 1874 by 100 with whole-number division gives 18, and multiplying back gives 1800, so every year falls into its century bin.

```
import csv

bins = {}
oldest = None
with open("City_Owned_Facilities.csv", encoding="utf-8-sig") as f:
    for row in csv.DictReader(f):
        year = int(row["YEAR_BUILT"])
        hundreds = year // 100 * 100
        key = (row["TYPE"], hundreds)
        bins[key] = bins.get(key, 0) + 1
        if oldest is None or year < oldest[0]:
            oldest = (year, row["TYPE"])

for key in sorted(bins):
    print(key[0], str(key[1]) + "s", bins[key])
print("oldest:", oldest)
```

### The oldest row

The earliest YEAR_BUILT in the file is 1824, on a Museum row, and the newest is 2016. Sorting all 82 years puts the middle of the list at 1926, so half the buildings the City lists are older than that.

### A label that hides things

Only 3 rows have the type Library, yet 9 building names contain the word LIBRARY. A community centre with a library inside is filed as a Community Centre, so a count by type undercounts libraries.

### A question to argue about

More than half the rows are Museum buildings, almost all from the 1800s. Should a chart of City buildings include them? There is no single right answer, which is the point of the exercise.

### What the file does not say

YEAR_BUILT tells us when a building was built, not when the City bought it, moved it or last renovated it. A building from 1850 may have been moved onto its site much later. Our students write those limits beside their chart before they present it.

## With AI tools everywhere, why should a Markham child learn if statements?

Because a decision written in code is only as good as the question behind it.

Ask an AI tool for a ride-height checker and it writes one instantly. Whether it says greater-than or greater-than-or-equal is a choice about a real child standing at 120 centimetres, and the tool makes that choice silently. A Grade 5 student who has tested the boundary themselves will catch it. A student who has never written an if statement will not know there was a choice.

That is why our children&rsquo;s classes put thinking first: say the yes-or-no question, write it, test the edge, explain the result. Children learn what AI is and how it errs, and they practise checking its answers, but no chatbot does their work in class. For home use, OpenAI requires that anyone under 18 has a parent&rsquo;s permission to use ChatGPT.

Ontario describes conditional statements as binary logic, a yes or a no; deciding which question deserves which answer is a human job. The longer argument is in [whether coding is still worth learning in 2026](/blog/is-coding-worth-learning-2026).
