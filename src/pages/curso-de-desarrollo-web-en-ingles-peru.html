La conexión

¿Vale la pena aprender desarrollo web en Perú?

Los datos del INEI dicen que el público de la web peruana creció mucho y muy rápido, sobre todo fuera de Lima. Quien construye sitios trabaja para un país que en buena parte acaba de llegar a internet.

Área20192026Diferencia en puntos (cálculo nuestro)

Datos del INEI (ENAHO), boletín técnico de TIC del segundo trimestre de 2026, Gráfico N° 1.6 (serie 2019 a 2026; 2026 preliminar). La última columna es una resta nuestra entre las dos primeras.

Entre el segundo trimestre de 2019 y el de 2026, los hogares peruanos con internet pasaron de 39,5 % a 64,5 %, una subida de 25 puntos según la serie del INEI. En el área rural el salto fue de 5,0 % a 27,1 %: más de cinco veces. Solo en el último año, el acceso nacional creció 3,8 puntos. Son millones de personas que hoy buscan, compran y hacen trámites en sitios web que alguien tiene que diseñar, programar y mantener.

Qué hacen esas personas en internet también está medido. El INEI registra que en el segundo trimestre de 2026 el 93,1 % de los usuarios de 6 años a más usó internet para entretenimiento, el 90,9 % para comunicarse y el 78,1 % para buscar información. Y el 90,2 % se conectó desde un celular. La consecuencia práctica para un desarrollador web peruano es clara: el sitio se diseña primero para la pantalla del teléfono y se prueba con conexión de datos, no con la fibra de la oficina.

El comercio que se mudó a la web

En su capítulo de economía digital (versión del 22 de junio de 2026), la guía que el gobierno estadounidense publica para sus exportadores estima que el comercio electrónico representa el 5,5 % del PBI peruano, frente al 2,4 % de 2019, y que aun así las compras en línea son solo el 8 % de las ventas minoristas.

Es decir, ya pesa en la economía y todavía tiene mucho por crecer. Cada bodega, restaurante o profesional independiente que se suma necesita una web, una tienda o al menos un catálogo que cargue rápido en un celular.

Lo que falta del lado del usuario

La encuesta Global Findex 2024, del Banco Mundial, encontró que solo el 15,9 % de los peruanos de 15 años a más había usado el celular o internet para comprar algo en línea.

Esa distancia entre lo que ya se puede comprar y lo que la gente compra se explica en parte por confianza. Un sitio claro, rápido y seguro es parte de la solución, y la seguridad es el tema de la lección de ejemplo.

El Estado también empuja la conexión: según una nota del MINEDU de septiembre de 2026, el plan es conectar 55,000 escuelas públicas a internet satelital. No tenemos relación con ese plan, pero es otra señal de que la próxima generación de usuarios de la web peruana viene de lugares que hasta hace poco no estaban en línea.

Full stack

¿Qué es el desarrollo web full stack?

Es saber construir las dos mitades de una aplicación web: lo que el usuario ve en su navegador y lo que ocurre en el servidor. Un desarrollador full stack no domina todo a la perfección; entiende cómo encajan las piezas y puede llevar un proyecto de principio a fin.

Las capas de una aplicación web (explicación nuestra)
CapaQué haceQué se aprende en el curso
Front endlo que se ve y se toca en el navegadorHTML, CSS, JavaScript y React
Back endrecibe pedidos, aplica reglas y respondeNode.js con Express, o Python con Django o Flask
Base de datosguarda la información de forma ordenadaSQL con MySQL, y una base de documentos como MongoDB
Desplieguepone la aplicación en internetun servidor en la nube, dominio y HTTPS

Una de las búsquedas que se repiten en Perú es "curso de desarrollo web html css y javascript", y tiene sentido empezar por ahí: son los tres lenguajes que entiende cualquier navegador del mundo. HTML dice qué hay en la página, CSS dice cómo se ve y JavaScript dice qué hace cuando el usuario interactúa. Lo que muchas personas descubren después es que una web útil, como una tienda o un sistema de reservas, necesita además un servidor y una base de datos. Ahí empieza lo que se llama back end, y quien maneja las dos mitades es full stack.

Una petición

El usuario toca "Buy" en su celular. El navegador envía una petición al servidor con lo que eligió.

Una regla

El servidor revisa que el producto exista, que haya stock y que los datos estén completos. Si algo falla, responde con un mensaje claro.

Una respuesta

Si todo está bien, guarda el pedido en la base de datos y el navegador muestra la confirmación. Todo en menos de un segundo.

Una lección de ejemplo

¿Por qué una web no debe mostrar el texto del usuario tal cual?

Porque el navegador no distingue entre el texto que escribió un visitante y el código de la página, a menos que el desarrollador se lo indique. Esta lección, escrita por nosotros, lo muestra con los comentarios de un restaurante.

  1. El comentario inofensivo. "Great ceviche!" sale igual en las dos versiones. Si el curso probara solo con comentarios así, nadie notaría el problema.
  2. El ampersand. En la versión 1, "Tom & Jerry fan" va tal cual. Muchos navegadores lo toleran, pero el HTML correcto es &amp;, que es lo que produce la versión 2.
  3. La negrita que nadie pidió. Un visitante escribió <b>BUY NOW</b>. En la versión 1, el navegador lo interpreta y el comentario aparece en negrita, gritando una oferta en la web del restaurante.
  4. El script. El cuarto comentario contiene <script>. En la versión 1, el navegador de cada visitante lo ejecutaría como código de la página. Este error tiene nombre en inglés, cross-site scripting o XSS, y es de los más conocidos de la web.
  5. La corrección. escape cambia &, < y > por sus equivalentes seguros. El navegador entonces los muestra como letras y no los ejecuta.

Los frameworks modernos como React escapan el texto por defecto, y por eso muchos estudiantes nunca ven este error, hasta el día en que usan una función que desactiva esa protección o escriben HTML a mano en el servidor. Preferimos que lo vean una vez, con un ejemplo inofensivo y controlado, y que entiendan por qué la regla existe. La frase que el estudiante explica al final, en inglés, es corta: "Never trust text that comes from a user."

Como reto, el mentor pide añadir un quinto comentario con comillas, por ejemplo She said "wow", y predecir cómo lo transforma escape. La respuesta se comprueba ejecutando: por defecto, la función también convierte las comillas, lo que importa cuando el texto va dentro de un atributo HTML.

Web e IA

¿Se puede aprender desarrollo web con IA?

Sí, y la IA cambia bastante el trabajo diario de un desarrollador web. Lo que no cambia es la responsabilidad: si la página tiene un agujero de seguridad, el que responde es quien la publicó.

Dónde ayuda

Generar la estructura inicial de una página, proponer estilos, explicar un error de la consola del navegador o traducir una función de JavaScript a Python.

En el curso para adultos se usan asistentes de código profesionales, incluidos los que piden 18 años. Con adolescentes, solo entran herramientas cuyos términos aceptan a menores de esa edad.

Dónde hay que mirar dos veces

En todo lo que toca datos de usuarios: formularios, contraseñas, consultas a la base de datos. El ejemplo de esta página es exactamente el tipo de detalle que una propuesta automática puede omitir.

En la accesibilidad: textos alternativos, contraste, navegación con teclado. Una web que solo funciona con mouse deja fuera a muchas personas.

La regla del curso es que el estudiante escribe primero una versión propia de cada tema, sin asistente, y solo después lo usa para acelerar. Así sabe reconocer cuándo la propuesta de la IA es correcta y cuándo solo lo parece. La misma idea guía nuestra oferta para todo el Perú, de primaria a profesionales.

En inglés

¿Por qué estudiar desarrollo web en inglés?

Porque la web se documenta en inglés: las referencias de HTML, CSS y JavaScript, las guías de React y Node.js, los mensajes de error del navegador y casi todas las preguntas y respuestas técnicas.

El EF EPI 2025 sitúa a Lima en 555 puntos, dentro de la banda alta de inglés. Para un desarrollador web peruano con ese nivel, el idioma deja de ser una barrera y se convierte en acceso: a documentación actualizada el mismo día en que sale una versión nueva, a comunidades internacionales y a clientes de otros países. Las clases en inglés entrenan además la parte que más cuesta, que es hablar: explicar una decisión de diseño, preguntar por un error o presentar un proyecto.

Si usted vive en otra ciudad del país, como Arequipa, no hay diferencia: las clases son en línea y el mentor se adapta a su horario. Hay una página en inglés sobre cómo enseñamos a estudiantes de Arequipa.

El nivel 4 suele ser el más nuevo: diseñar una API y defenderla de datos mal intencionados.

Desarrollo web en inglés: preguntas frecuentes

¿Las clases son en español?

No. Este curso se da íntegramente en inglés, siempre en vivo por internet. Lo planteamos como ventaja: la documentación de la web está en inglés, y practicar el idioma hablando de su propio código, con un mentor que va a su ritmo, acelera las dos cosas. En el EF EPI 2025, Lima figura en la banda alta de inglés.

¿Qué es el desarrollo web full stack?

Es saber construir tanto la parte que ve el usuario en el navegador (front end) como el servidor y la base de datos (back end). Un desarrollador full stack puede llevar una aplicación web de principio a fin.

¿Tengo que saber programar antes?

No. El curso empieza con HTML y CSS, que se aprenden rápido y dan resultados visibles en la primera semana, y luego pasa a JavaScript.

¿Cuánto tiempo toma?

Nuestra ruta de referencia es de unos ocho meses desde cero hasta una aplicación publicada, con dos clases por semana. Quien ya programa suele avanzar más rápido.

¿Aprenderé HTML, CSS y JavaScript?

Sí, son los tres primeros temas. Después se suman React, Node.js o Python y una base de datos SQL.

¿Se usa inteligencia artificial?

Sí, como apoyo y después de que el estudiante sabe hacerlo solo. Los adultos usan asistentes profesionales; los adolescentes, solo los permitidos para su edad. Todo lo que toca datos de usuarios se revisa a mano.

¿A qué hora puedo tomar las clases?

Cualquier día y a cualquier hora, con total flexibilidad: elija una clase grupal o, para un plan muy personalizado, clases individuales a la hora que mejor le convenga a su familia. Entre ambos países hay una diferencia fija de 10 horas y media; una sesión a las 6:30 a. m. de Lima es a las 5:00 p. m. para el mentor.

¿En qué moneda se cobra?

En dólares estadounidenses y por tarjeta; la conversión corre por cuenta de su banco. Para la sesión inicial no se piden datos de pago.

¿Me ayudan a conseguir clientes o trabajo?

No tenemos bolsa de empleo y no prometemos ingresos. El curso le deja un portafolio de sitios publicados y código en GitHub, que es lo que puede mostrar a un cliente o a una empresa.

¿El curso tiene validez oficial?

No. No tenemos vínculo con el MINEDU, la SUNEDU, universidades ni institutos, y no damos títulos ni créditos. Al terminar entregamos una constancia de finalización propia.
