## What actually happens in a live online Python class

Below is the order of one of our teens' Python lessons, written as an example plan. Lengths vary by course and level, but the order holds: the student types more than the teacher talks.

**One live lesson for a Grade 9 Python student in Vaughan, in order (an example plan written by us)**

| Step | What the teacher does | What the student does |
|---|---|---|
| 1. Warm-up | Puts last week's program on the shared screen with one line broken | Finds the broken line and says why it fails before touching the keyboard |
| 2. New idea | Shows one new construct, for example a dictionary that counts | Predicts the output of a four-line example, then runs it |
| 3. Build | Watches the student's own editor and stays quiet unless the student is stuck for long | Writes a small program that uses the new idea on a fresh problem |
| 4. Break it | Changes one input so the program gives a wrong answer | Traces the values by hand and fixes the logic, not just the symptom |
| 5. Explain | Asks the student to talk through the finished code | Explains each block in plain words, as if to a classmate |
| 6. Next step | Sets one short task and notes what to revisit | Writes the task down and asks anything left unclear |

Steps 4 and 5 are where a live class earns its time. A recorded video cannot change the input on a student's program, and a chatbot will happily fix the code for them. Our teachers do neither the typing nor the thinking for the student; they ask the next question.

### Code on a shared screen

The student writes in their own editor and shares it, so the teacher reads the real code, typos included. Nothing is pasted in from a finished answer.

### A batch of fifteen to twenty

Everyone in the batch is at the same stage. The teacher calls on students by name, and code from two or three of them is read aloud each class.

### One to one

One teacher, one student, a pace set by that student. Families pick it for faster progress, for ICS4U project work or for CCC practice.

## From a first print() to a real project, step by step

Vaughan students already meet code in Ontario math class. Each step below is ours; the right-hand column quotes the Ontario expectation it builds on, read from the ministry curriculum service on 22 October 2026.

**Our Python path for Vaughan students, matched to Ontario expectations (expectation wording quoted from Ontario's curriculum service; the steps are ours)**

| Our step | What the student can do after it | Ontario expectation it extends |
|---|---|---|
| 1. Run and change | Run a short program, change one value, explain the new output | Grade 1 C3.2: &ldquo;read and alter existing code&rdquo; and describe how changes affect the outcomes |
| 2. Loops and choices | Write for loops and if statements without copying an example | Grade 6 C3.2: changes to &ldquo;the outcomes and the efficiency of the code&rdquo; |
| 3. Functions | Split a problem into named functions with inputs and a return value | Grade 7 C3.1: events influenced by &ldquo;a defined count and/or subprogram&rdquo; |
| 4. Algebra in code | Model a rule with variables, then test it against values | MTH1W C2.2: &ldquo;create code by decomposing situations into computational steps&rdquo; |
| 5. Data | Read a file, count and sum by group, and state what the result leaves out | Grade 8 C3.1: code that analyses data so students can &ldquo;communicate decisions&rdquo; |
| 6. A project | Plan, build, test and document a program of several hundred lines | ICS4U: &ldquo;modular design principles to create complex and fully documented programs&rdquo; |

The numbering is a sequence, not a calendar. A Grade 5 child may spend months on steps 1 and 2 with games and turtle drawings; an adult with spreadsheet experience may reach step 5 within weeks. What we never do is skip step 1. A student who cannot predict what a changed line will print is not ready for a project, whatever their age.

## How many kilometres of cycling routes did Vaughan supply to the regional file?

York Region publishes a Bike Path layer for the whole region. Each line records who supplied it, so a student can pull out the lines whose SOURCE is Vaughan and measure them. Every number below is our own count of that download.

**Our sum of line lengths in the York Region Bike Path layer, rows with SOURCE = Vaughan (238 rows, downloaded 22 October 2026). Lengths come from each line's geometry in metres, converted to km**

| Facility class in the file | Kilometres of line |
|---|---|
| Shared Pathway (in-boulevard) | 36.0 |
| Off-Road Multi-Use Trail | 26.7 |
| Cycle Track | 20.6 |
| Paved Shoulder | 10.1 |
| Cycle Track (Region Maintained) | 8.0 |
| Bike Lane | 7.8 |
| Off-Road Hiking Trail | 3.8 |
| Shared Roadway (signed route) | 0.9 |
| Painted Bike Lane (Region) | 0.4 |
| Connection | 0.1 |

The script below printed every figure in the table. It needs nothing beyond Python's built-in modules and reads the JSON file saved from the York Region map service:

```
import json
from collections import defaultdict

with open("bike-path-source-vaughan.json", encoding="utf-8") as f:
    rows = [feat["attributes"] for feat in json.load(f)["features"]]

km_by_class = defaultdict(float)
owners = defaultdict(int)
for row in rows:
    km_by_class[row["BIKE_FACILITY_CLASS"]] += row["SHAPE.STLength()"] / 1000
    owner = (row["OWNER"] or "no owner listed").strip().upper()
    owners[owner] += 1

print(len(rows), "rows")
for name, km in sorted(km_by_class.items(), key=lambda p: p[1], reverse=True):
    print(f"{name}: {km:.1f} km")
print(dict(owners))
```

### Why a defaultdict

A defaultdict(float) starts every new facility class at 0.0, so the loop can add a length without first checking whether the class exists. It is the same counting idea as a tally chart, with decimals.

### Two length columns

The file has ACTUAL_LENGTH and a geometry length. ACTUAL_LENGTH is blank in 6 of the 238 rows and differs from the geometry by more than half a metre in 20, so our script sums the geometry, which every row has.

### Labels that almost match

The OWNER column holds &ldquo;CITY OF VAUGHAN&rdquo; on 88 rows and &ldquo;Vaughan&rdquo; on 4. Calling upper() merges York Region with YORK REGION, but the two Vaughan labels stay apart, and 112 rows list no owner at all.

### What the 114.2 km does and does not say

Adding the rows gives 114.2 km of line that Vaughan supplied to the regional file. That is our sum, not a figure York Region or the City publishes, and it is not the length of every route in Vaughan: lines supplied by others are excluded, and two lines can describe the same stretch. A student who writes that sentence has understood the data.

A sensible next task is a judgment call, not more code: should &ldquo;CITY OF VAUGHAN&rdquo; and &ldquo;Vaughan&rdquo; be merged, and what should a program do with 112 blank owners? Students write the rule down before writing the line that applies it. The data is used under the York Region Open Data Licence: contains public sector information made available under The Regional Municipality of York's Open Data Licence ([York Region open data](https://insights-york.opendata.arcgis.com/)). Nothing here is endorsed by York Region.

## If AI can write Python, what is a Vaughan student learning?

How to tell whether the Python an AI tool writes is right, which is a skill only writing it yourself builds.

An AI assistant asked for the kilometres of Vaughan cycling routes would sum something and print a confident number. It would not stop to ask which length column to trust, whether two owner labels mean the same city, or whether the lines Vaughan supplied are the whole network. Those questions decided every figure on this page.

So we teach thinking before tools. Students solve the problem, write the code and question the output; later, older students use AI assistants under the age rules we follow, as a second opinion they must check, never as a way to copy an answer.

A student who can explain why 114.2 km is not the length of every route in Vaughan has learned the part of programming that does not get automated. The longer argument is in [our essay on learning to code beside AI](/blog/is-coding-worth-learning-2026).
