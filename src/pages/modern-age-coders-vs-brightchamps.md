### Where the two are genuinely alike

Live teaching, a teacher on screen, groups or one to one, blocks for young beginners and typed languages later: on all of these, BrightCHAMPS' Canada page and ours describe much the same thing. A family who wants live online classes rather than videos or a centre can be well served by either.

That is worth saying plainly, because it means the choice is a matter of fit, not of one school doing the job and the other not.

### Where they part

The differences are structural. BrightCHAMPS builds its coding offer as a set of courses for each grade band, inside a wider menu of children's subjects. We build one long coding and math path whose later stages are Canadian school computer science, contest preparation and courses for adults.

Neither shape is right for every child. The sections below show what each looks like and who it tends to suit.

## How we teach debugging: say what you expect, then make the code show its work

This walkthrough is ours, written for our teen classes; it is not from BrightCHAMPS or any other course. The bug is a common one, the kind that turns up in a first school computer science assignment. What matters is the order of the steps, which we repeat until students do it without being asked.

**Our example · the program a student brings in** (python)
```python
# Our worked example: a quiz-average bug, as a student might bring it to class
scores = [7, 9, 6, 10]

total = 0
for i in range(1, len(scores)):
    total = total + scores[i]

average = total / len(scores)
print("Average:", average)
```
We ran it on 22 October 2026. It prints Average: 6.25. The student is sure the scores average 8.

1. State the expectation. Before touching the code, the student works it out by hand: 7 + 9 + 6 + 10 = 32, and 32 / 4 = 8.0. Now there is a definite gap between 8.0 and 6.25 to explain.
2. Make the loop show its work. Instead of guessing, the student adds one print line inside the loop so the program reports every value it adds.
3. Read the evidence. The output shows indexes 1, 2 and 3 only. The first score, 7, is never added: 9 + 6 + 10 = 25, and 25 / 4 = 6.25. The bug is now found, not guessed.
4. Fix the cause, not the symptom. range(1, len(scores)) starts at 1. The cleanest fix loops over the scores themselves, so there is no index to get wrong.
5. Write a test that would have caught it. A list whose first score is the only large one, [100, 0, 0, 0], must average 25.0. The old code would print 0.0 for it, so the test proves the fix.

**Step 2 · the loop shows its work** (python)
```python
# Step 2: make the loop show its work
scores = [7, 9, 6, 10]

total = 0
for i in range(1, len(scores)):
    print("adding index", i, "value", scores[i])
    total = total + scores[i]

average = total / len(scores)
print("Average:", average)
```

**What step 2 prints** (text)
```text
adding index 1 value 9
adding index 2 value 6
adding index 3 value 10
Average: 6.25
```

**Step 4 · the fix and the test** (python)
```python
# Step 4: the fix, and a test chosen to catch the old bug
def average(scores):
    total = 0
    for s in scores:          # every score, first one included
        total = total + s
    return total / len(scores)

print("Average:", average([7, 9, 6, 10]))
print("Test:", average([100, 0, 0, 0]))
```

**What the fixed version prints** (text)
```text
Average: 8.0
Test: 25.0
```
Both lines confirmed on 22 October 2026. The second line is the test written to catch the original bug.

### Why the order matters

Students who skip step 1 cannot tell whether a change helped, because they never said what right looks like. Students who skip step 2 change lines at random until something works, and learn nothing about why.

The habit transfers to any language. In Java the print line becomes System.out.println, and the steps stay the same.

### Where this sits in a Canadian course

Loops over a list of marks are standard early material in Ontario Grade 11 computer science, and an off-by-one start is one of the most common slips. A companion class turns the slip into a lesson rather than a lost mark.

For contest students, step 5 is the important one: the CCC grader tests code on inputs the student never sees, so writing your own awkward test is part of preparation.

## Four checks before you choose a live online school

These apply to any online coding school, including the two on this page.

1. Ask who teaches. Will your child have the same teacher each week? Continuity is what lets a teacher spot a recurring slip.
2. Ask what happens after this course. When the course or grade band ends, where does your child go next, and does the school know Canadian school courses and contests?
3. Ask about class times in your province. A class set in one time zone can land awkwardly in British Columbia or Newfoundland. Check the time in your own clock, including after the clocks change.
4. Take the free first class at both. Afterwards, ask your child to explain one thing they made. The class that left them able to explain more is usually the right one.

Families comparing more than two schools may find our [coding classes in Canada](/coding-classes-in-canada) hub useful, and our [Canadian time zones page](/canada-time-zones-2026-online-class-times) covers class times for every province.
